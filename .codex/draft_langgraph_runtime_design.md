## 첫 학습

설계 글은 긴 실행의 지연, 재시도 비용, 비결정성을 출발점으로 삼는다. 병렬화·스트리밍·체크포인트·사람의 개입·추적·태스크 큐가 요구사항이다. 태스크 큐는 글 당시 라이브러리 밖의 플랫폼 영역이다.

핵심 선택은 실행을 명시적인 단계로 구조화하는 것이다. 단계 사이에 결과를 전달하면 엔진이 실행 진행을 관리할 수 있다.

### 학습용 예시: 검색 결과를 받은 뒤 사용자 승인을 기다리는 작업

아래는 개념 설명을 위한 예시이며 DeepAgents의 실제 노드 구성을 뜻하지 않는다.

```text
모델 판단 → 검색 실행 → 결과 반영 → 승인 요청 → 후속 작업
```

단일 함수의 지역 변수에 검색 결과를 넣고 대기하면, 프로세스 종료 후 그 변수와 실행 위치는 사라진다. 결과를 저장 가능한 상태로 표현하고 실행을 이어갈 정보를 함께 관리하면, 다른 프로세스에서도 복구를 설계할 수 있다.

체크포인트는 Python 호출 스택 전체를 보존하는 기능으로 이해하면 안 된다. `interrupt()`로 중단된 노드는 재개 시 처음부터 실행되므로 중단 전 부수 효과의 반복 가능성을 고려한다. 상세 규칙은 후속 학습에서 다룬다.

Pregel은 실행 대상 선택 → 노드 실행 → 채널 갱신 순서로 진행한다. 같은 단계의 노드가 쓰는 채널 업데이트는 다음 단계부터 보인다. 이것은 실행 중 공유 상태를 제각각 수정하는 방식과 다른 상태 전달 규칙이다.

## 이어서 공부할 질문

1. 어떤 채널의 변경이 어떤 노드를 실행시키는가?
2. 채널 버전과 노드가 관찰한 버전은 왜 필요한가?
3. 병렬 노드의 업데이트를 어떻게 병합하는가?
4. 체크포인트에는 상태 외에 어떤 실행 정보가 필요한가?
5. 설계 글의 성능 주장을 현재 구현과 어떻게 대조할 것인가?
