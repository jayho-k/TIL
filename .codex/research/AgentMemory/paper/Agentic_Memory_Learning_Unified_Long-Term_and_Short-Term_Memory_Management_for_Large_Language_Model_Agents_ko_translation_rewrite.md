## 초록

대규모 언어 모델(LLM) 에이전트는 유한한 컨텍스트 창 때문에 장기 시간 범위의 추론에서 근본적 한계에 직면하므로, 효과적인 메모리 관리가 중요하다. 기존 방법은 보통 장기 메모리(LTM)와 단기 메모리(STM)를 별도 구성 요소로 다루고 휴리스틱이나 보조 제어기에 의존한다. 이는 적응성과 종단 간 최적화를 제한한다. 본 논문은 LTM과 STM 관리를 에이전트 정책에 직접 통합하는 통합 프레임워크 Agentic Memory(AgeMem)를 제안한다. AgeMem은 메모리 연산을 도구 기반 행동으로 노출하여 LLM 에이전트가 무엇을 언제 저장·검색·갱신·요약·폐기할지 자율적으로 결정하게 한다. 이러한 통합 행동을 학습시키기 위해 3단계 점진적 강화학습 전략을 제안하고, 메모리 연산이 유발하는 희소하고 불연속적인 보상을 다루기 위해 단계별 GRPO를 설계한다. 다섯 장기 시간 범위 벤치마크 실험은 AgeMem이 여러 LLM 백본에서 강력한 메모리 증강 기준선을 일관되게 앞서며, 과제 성능·장기 메모리 품질·컨텍스트 사용 효율을 개선함을 보인다.

## 1. 서론

다단계 추론과 복잡한 워크플로를 포함하는 장기 에이전트 과제(Chang et al., 2024)에서 LLM 에이전트의 효과는 특정 순간에 주의를 기울일 수 있는 정보에 근본적으로 제약된다. 여기서는 이를 통틀어 에이전트의 메모리라고 부른다(Xiong et al., 2025; Goodyear et al., 2025). 메모리는 보통 두 범주로 나뉜다. 장기 메모리(LTM)는 사용자 또는 과제별 지식을 지속적으로 저장하고(Zhong et al., 2024; Jiang et al., 2024), 단기 메모리(STM)는 현재 입력 컨텍스트에 포함된 정보로 이루어진다(Wu et al., 2025b; Gao et al., 2025b). 고품질 LTM은 축적된 지식을 효율적으로 검색하도록 돕고, 효과적인 STM 관리는 중복을 줄이며 두드러진 컨텍스트를 보존한다. 두 메모리를 함께 관리하면 유한한 컨텍스트 창의 한계를 완화하므로, 복잡한 추론 환경에서 에이전트 성능을 높이는 데 이들의 공동 관리가 중요하다.

그러나 기존 연구는 LTM과 STM을 주로 독립 구성 요소로 취급했다. STM은 MainRAG(Chang et al., 2025)와 ReSum(Wu et al., 2025a)처럼 검색 증강 생성(RAG)(Pan et al., 2025b)으로 강화하는 경우가 많다. 이 방법들은 외부 검색 또는 주기적 요약으로 사용 가능한 컨텍스트를 넓힌다. 일부 과제에서 효과적이지만, 사전에 정한 일정이나 휴리스틱 규칙에 크게 의존하기 때문에 드물게 나타나지만 중요한 세부 정보를 놓칠 수 있고 불필요한 잡음을 넣을 수 있다(Ma et al., 2025; Dong et al., 2025). 반면 LTM 관리는 별개 계통으로 발전했으며, 보통 트리거 기반(Kang et al., 2025; Wang and Chen, 2025; Wang et al., 2025c; Chhikara et al., 2025)과 에이전트 기반(Yan et al., 2025; Hu et al., 2025; Xu et al., 2025) 패러다임으로 나뉜다. 전자는 미리 정한 시점에 고정된 메모리 연산을 수행하고, 후자는 특수 메모리 관리자를 두어 무엇을 어떻게 저장할지 결정한다. 더 유연하더라도 대부분은 여전히 수작업 규칙이나 보조 전문가 모델에 의존하며, 이는 적응성을 제한하고 시스템 복잡도를 높인다(Xiong et al., 2025).

그 결과 LTM과 STM은 보통 분리되고 느슨하게 결합된 모듈로 다뤄진다. 그림 1이 보이듯 기존 구조는 대개 (a) 정적 STM과 트리거 기반 LTM, 또는 (b) 정적 STM과 에이전트 기반 LTM의 두 패턴을 따른다. 두 경우 모두 두 메모리 시스템을 독립적으로 최적화한 뒤 임시방편으로 결합하므로, 메모리 구성이 단절되고 장기 시간 범위 추론 과제에서 최적이 아닌 성능에 이른다. 따라서 LTM과 STM 관리를 통합하는 일은 필요하지만 대체로 탐구되지 않은 도전 과제로 남아 있다.

그럼에도 통합 메모리 관리를 이루려면 세 가지 근본 과제를 풀어야 한다. (C1) **기능 이질성 조정**: LTM과 STM은 서로 다르면서 보완적인 역할을 한다. LTM은 무엇을 저장·갱신·폐기할지 결정하고, STM은 활성 컨텍스트에서 무엇을 검색·요약·제거할지 관장한다(Zhang et al., 2025b). 과제는 이들의 상호작용을 상승효과가 나도록 조율하는 통합 기제를 설계하는 일이다. (C2) **학습 패러다임 불일치**: 기존 강화학습(RL) 프레임워크는 두 메모리 유형에 현저히 다른 학습 전략을 적용한다(Ma et al., 2024). LTM 중심 학습은 상호작용 전에 이용 가능한 세션 수준 정보를 활용하는 일이 많은 반면, STM 학습은 장기 컨텍스트를 흉내 내기 위해 방해 요소를 주입한다(Sun et al., 2024). 또한 표준 RL은 안정적 보상을 가진 연속 궤적을 가정하지만, 메모리 연산이 본질적으로 만드는 단편적·불연속적 경험(Wu et al., 2025a)과 충돌하므로 종단 간 최적화가 특히 어렵다. (C3) **실제 배포 제약**: 많은 에이전트 시스템은 메모리 제어를 보조 전문가 LLM에 의존하여 추론 비용과 학습 복잡도를 크게 키운다. 외부 전문가 모델에 의존하지 않고 통합 메모리 관리를 에이전트에 직접 넣는 방법은 열린 문제로 남아 있다.

이 과제를 해결하기 위해 그림 1 오른쪽과 같은 Agentic Memory(AgeMem)를 제안한다. 메모리를 외부 구성 요소로 다루는 선행 설계와 달리 AgeMem은 두 메모리 유형을 에이전트의 의사결정 과정에 직접 통합한다. 통합 도구 기반 인터페이스를 통해 LLM은 LTM과 STM의 메모리 연산을 자율적으로 호출하고 실행한다. 또한 모델이 먼저 LTM 저장 능력을 습득하고, 다음으로 STM 컨텍스트 관리를 배우며, 마지막으로 완전한 과제 설정에서 두 메모리 형태를 조정하게 하는 3단계 점진적 RL 전략을 설계한다. 단계 간 단편화된 경험 문제를 해결하기 위해 출력 보상을 이전 메모리 결정까지 전파하는 단계별 Group Relative Policy Optimization(GRPO)(Shao et al., 2024)를 설계한다. 이는 RL의 희소하고 불연속적인 보상이 만드는 어려움을 완화한다. 다섯 장문맥·추론 집약 벤치마크에서의 평가는 AgeMem이 강력한 기준선을 일관되게 앞서며 통합 메모리 관리의 효과를 검증함을 보인다.

본 논문의 기여는 다음과 같다.

- LLM 기반 에이전트가 장기·단기 메모리를 언제, 무엇을, 어떻게 관리할지 자율적으로 결정하게 하는 통합 에이전트 메모리 프레임워크 AgeMem을 제안한다.
- 통합 메모리 관리 행동을 효과적으로 종단 간 학습하도록 단계별 GRPO를 갖춘 3단계 점진적 RL 전략을 개발한다.
- 여러 모델과 장기 시간 범위 벤치마크에서 종합 평가하여, 복잡한 에이전트 과제에서의 견고성과 효과를 보인다.

> 그림 1. 독립 메모리 관리 프레임워크와 통합 메모리 관리 프레임워크의 비교. (왼쪽) 정적 STM과 트리거 기반 LTM을 쓰는 전통 프레임워크. (가운데) STM은 정적으로 유지하되 메모리 관리자가 에이전트 방식으로 LTM을 제어하는 독립 프레임워크. (오른쪽) 명시적 도구 기반 연산을 통해 LTM과 STM을 공동으로 지능적으로 관리하는 제안 AgeMem 프레임워크.

## 2. 배경 및 관련 연구

### 장기 메모리(LTM)

지속적 LTM은 긴 시간 범위에서 동작하는 LLM 기반 에이전트에 중요하다(Wang et al., 2025b; Li et al., 2025). 최근 연구는 LTM을 모델링하는 다양한 구조 설계를 탐색했다. LangMem(LangChain Team, 2025)은 여러 메모리 유형을 지원하는 모듈형 프레임워크를 제공한다. A-Mem(Xu et al., 2025)은 구조화된 지식 단위를 연결하여 통합을 촉진하는 Zettelkasten 영감 설계를 채택한다. Mem0(Chhikara et al., 2025)은 확장 가능한 추출-갱신 파이프라인을 제안하고, 구조화된 추론을 위한 그래프 기반 변형으로 확장한다. Zep(Rasmussen et al., 2025)은 세션 간·시간 인지 추론을 가능하게 하도록 메모리를 시간적 지식 그래프로 표현한다. 이 접근법들은 정보를 구성하고 검색하는 데 효과적이지만, 대체로 미리 정의된 메모리 구조나 휴리스틱 갱신 규칙에 의존한다. 메모리가 커질수록 이러한 설계는 시스템 복잡도가 증가하고 우선순위화와 망각을 위한 적응적·학습 기반 전략이 부족해지는 문제가 있다. 반대로 본 연구는 과제 요구와 장기 효용에 따라 무엇을 저장·갱신·망각할지 에이전트가 동적으로 결정하도록 적응적 메모리 정책을 학습하는 데 목적이 있다.

### 단기 메모리(STM)

에이전트형 LLM에서 STM은 주로 컨텍스트 선택과 검색을 뜻한다(Wang et al., 2024; Jin et al., 2024). RAG(Pan et al., 2025b; Salama et al., 2025; Kagaya et al., 2024)는 검색된 내용을 프롬프트에 주입하여 사용 가능한 컨텍스트를 넓히는 지배적 패러다임이다. 효과적이지만 장기 시간 범위에서 컨텍스트 폭증을 근본적으로 막지 못하고 무관하거나 산만한 정보를 넣을 수 있다. 이 문제를 다루기 위해 ReSum(Wu et al., 2025a)은 상호작용 이력을 압축된 추론 상태로 주기적으로 압축하여, 에이전트가 고정 컨텍스트 창 제약을 넘어 동작하게 한다. 그러나 요약 일정은 대체로 미리 정해져 있으며, 과도한 압축은 드물지만 중요한 세부 정보를 버릴 위험이 있다. 본 접근법은 에이전트가 컨텍스트를 언제 어떻게 검색·요약·필터링할지 학습하게 하므로, 효율성과 정보 보존 사이에서 더 유연한 균형을 이룬다.

### LLM을 위한 강화학습

강화학습은 LLM 기반 에이전트의 의사결정과 추론 능력을 개선하는 효과적인 패러다임이 되었다(Yao et al., 2023; Jin et al., 2025; Qian et al., 2025; Chaudhari et al., 2025). 최근 발전 중 GRPO(Shao et al., 2024)는 표본 궤적의 상대적 품질을 바탕으로 정책을 최적화하여, 명시적 가치 함수 없이 안정성을 높인다. GRPO와 변형(Gilabert et al., 2025; Wang et al., 2025a)은 복잡한 추론 과제에서 강한 성능을 보였다. 그러나 기존 RL 기반 시스템은 일반적으로 메모리를 정적 또는 외부 구성 요소로 취급하므로, 메모리 연산과 관련된 불연속·단편 궤적에는 적합하지 않다(Yan et al., 2025; Zhang et al., 2025a). 반대로 본 연구는 RL을 메모리 관리 과정에 직접 통합하여 언어 생성과 메모리 연산을 함께 학습한다.

### RL 기반 메모리 에이전트와의 관계

최근 연구(Yan et al., 2025; Zhang et al., 2025a)는 메모리 연산을 행동으로 모델링하고 이를 최적화하기 위해 RL을 적용하므로, 표면적으로는 본 접근과 비슷하다. 그러나 이 방법들은 보통 메모리의 한 측면만 한 번에 최적화하고, 검색·요약·단기 컨텍스트 처리는 고정 휴리스틱 또는 별도로 조정된 모듈로 둔다. 따라서 이른 저장 결정과 나중의 추론 행동은 느슨하게만 연결되고, 학습 신호가 둘을 명시적으로 잇지 않는다. AgeMem은 지연된 감독 아래 메모리 사용을 하나의 학습 가능한 제어 문제로 정식화한다. 즉 지속 LTM 연산과 문맥 STM 연산을 모두 포함하는 이질적 메모리 행동에 대한 통합 정책을 종단 간 학습하므로, 저장·검색·필터링·요약 결정이 같은 최종 과제 보상에 대해 함께 최적화된다.

## 3. 방법

AgeMem은 LLM 에이전트가 LTM과 STM을 종단 간으로 자율 관리하게 하는 통합 메모리 프레임워크다. 그림 1 오른쪽처럼 특수 도구 집합을 통해 메모리 관리 능력을 에이전트에 직접 통합하고, 3단계 점진 전략을 통해 통합 메모리 관리의 최적 전략을 학습하게 한다.

### 3.1 문제 정식화

**AgeMem의 통합 RL 정식화.** 각 시점 $t$에서 에이전트는 대화 컨텍스트(단기 메모리) $C_t$, 장기 메모리 저장소 $M_t$, 과제 명세 $T$로 이루어진 상태 $s_t\in\mathcal S$를 관측한다.

$$s_t=(C_t,M_t,T).$$

명세 $T$에는 입력 질의 $q$, 문맥 정보 $I_q$, 그리고 학습 중에만 제공되는 기대 정답 $A_q$가 포함된다. 이 정식화는 에이전트가 일시적 컨텍스트와 지속 지식을 모두 바탕으로 의사결정을 내리게 한다.

상태 $s_t$가 주어지면 에이전트는 언어 생성과 메모리 연산을 포함하는 혼합 행동 공간 $\mathcal A$에서 행동 $a_t\in\mathcal A$를 고른다. 이 결정은 매개변수 정책 $\pi_\theta$가 담당하며, $\pi_\theta(a_t\mid s_t)=P(a_t\mid s_t;\theta)$이고 $\theta$는 LLM 매개변수이며 $a_t\sim\pi_\theta(\cdot\mid s_t)$다. 궤적 $\tau=(s_1,a_1,\ldots,s_T,a_T)$에 대한 누적 보상은 다음과 같이 정의한다.

$$R(\tau)=\sum_iw_iR_i(\tau)+P_{penalty}(\tau).\tag{1}$$

$R_i$는 과제 성능과 메모리 품질을 포착하고, $P_{penalty}$는 중복 저장·과도한 도구 사용·통제되지 않은 컨텍스트 확장을 억제한다. 최적화 목표는 다음과 같다.

$$\theta^*=\arg\max_\theta\mathbb E_{\tau\sim\pi_\theta}[R(\tau)].\tag{2}$$

이 정식화는 수작업 휴리스틱을 학습 가능한 기제로 바꾸며, 메모리 관리를 에이전트 정책의 필수 구성 요소로 취급한다.

**3단계 궤적 구조.** 장기 상호작용을 포착하고 메모리 능력을 점진적으로 학습하기 위해 각 궤적을 세 연속 단계 $\tau=(\tau^{(1)},\tau^{(2)},\tau^{(3)})$로 나누며, 총 길이는 $T=T_1+T_2+T_3$이다. 1단계에서 에이전트는 일상적 상호작용을 하며 유용한 정보를 LTM에 저장할 수 있다. 2단계에서는 방해 또는 무관 콘텐츠가 들어오며, 선택적 보존과 압축을 통해 STM을 관리해야 한다. 3단계에서는 보존된 컨텍스트와 이전에 쌓인 LTM을 조정하여 써야 하는 과제가 주어진다. 이 설계의 핵심은 LTM $M_t$가 모든 단계에 걸쳐 지속된다는 점이다. 반대로 컨텍스트 $C_t$는 단계 사이 정보 누출을 막기 위해 1단계와 2단계 사이에서 초기화된다. 2단계 전 초기화는 에이전트가 남은 컨텍스트로 최종 과제를 풀지 못하게 하므로, LTM에서 제대로 검색하도록 강제하고 메모리 연산을 효과적으로 학습하게 한다.

매 단계에서 경험 튜플 $e_t=(s_t,a_t,r_t,\log\pi_{\theta_{old}}(a_t\mid s_t))$를 수집한다. 여기서 중간 단계의 $r_t$는 보통 0이고 궤적 완료 후 부여되며, $\log\pi_{\theta_{old}}(a_t\mid s_t)$는 이전 정책 $\pi_{\theta_{old}}$ 아래의 로그 확률이다. 이 표현은 GRPO(Shao et al., 2024)에서 단계별 공적 할당을 가능하게 하며, 에이전트가 단계 전반의 특정 메모리 결정에 장기 보상을 귀속하게 한다. 단계로 나뉘지만 연속적인 방식으로 궤적을 구성함으로써, 에이전트는 견고한 장기 추론에 필요한 시간적으로 일관되고 과제 적응적인 메모리 정책을 학습한다.

> 표 1. AgeMem에서 장기 메모리(LTM)와 단기 메모리(STM)를 조작하는 메모리 관리 도구.

| 도구 | 대상 | 기능 |
| --- | --- | --- |
| `ADD` | LTM | $M_t$에 새 지식 추가 |
| `UPDATE` | LTM | $M_t$의 항목 수정 |
| `DELETE` | LTM | $M_t$의 항목 제거 |
| `RETRIEVE` | STM | $M_t$의 항목을 $C_t$로 검색 |
| `SUMMARY` | STM | $C_t$의 구간 요약 |
| `FILTER` | STM | $C_t$에서 무관 구간 필터링 |

### 3.2 도구 인터페이스를 통한 메모리 관리

AgeMem은 명시적 도구 인터페이스를 통해 LLM 에이전트에 메모리 관련 연산을 노출한다(표 1). 에이전트는 `ADD`, `UPDATE`, `DELETE`로 지속 LTM을 수정하고, `RETRIEVE`, `SUMMARY`, `FILTER`로 STM을 세밀하게 제어한다. 이 도구들을 행동 공간에 넣음으로써 메모리 제어는 외부 휴리스틱 파이프라인이 아니라 의사결정의 내재적 구성 요소가 된다. 이 설계는 과제 구조, 이력, 컨텍스트에 따라 에이전트가 메모리를 적응적으로 관리하게 한다.

각 도구는 메모리 관리에서 구별되는 기능을 맡는다. LTM 연산 중 `ADD`는 LTM 저장소 $M_t$에 새 항목을 삽입한다. `UPDATE`는 `memory_id`로 식별한 기존 항목을 수정한다. `DELETE`는 오래된 지식이 쌓이지 않게 $M_t$에서 항목을 제거한다. STM 연산 중 `RETRIEVE`는 $M_t$에서 의미적으로 가장 관련 있는 상위 $k$개 기억을 활성 컨텍스트 $C_t$로 가져온다. `SUMMARY`는 지정 상호작용 이력 구간을 본질 정보를 보존한 간결한 표현으로 압축해 컨텍스트 크기를 줄인다. `FILTER`는 주어진 기준과의 의미 유사도가 임계값 $\theta_f$를 넘는 컨텍스트 메시지를 제거하여 무관하거나 산만한 콘텐츠를 억제한다. 이 여섯 연산은 에이전트에게 표현력이 있으면서도 해석 가능한 메모리 수명주기 제어를 제공한다. 정확한 형식 정의와 시스템 프롬프트는 부록 A.1에 제시한다.

### 3.3 3단계 점진적 RL 전략

통합되고 안정적인 메모리 행동을 학습하기 위해 점진적 3단계 학습 전략을 제안한다. 각 과제 인스턴스 $q\in\mathcal T$에서 에이전트는 완전한 궤적을 생성한다.

$$\tau_k^{(q)}=(\tau_k^{(1)},\tau_k^{(2)},\tau_k^{(3)}),\quad k=1,\ldots,K,\tag{3}$$

여기서 $K$는 독립 rollout 수이고, 각 부분 궤적 $\tau_k^{(i)}$는 특정 학습 단계에 대응한다.

**1단계(LTM 구성).** 에이전트는 일상 대화 환경에서 문맥 정보 $I_q$에 노출된다. 목표는 두드러진 정보를 식별해 LTM $M_t$에 저장하는 것이다. 상호작용 중 STM $C_t$는 자연스럽게 변하고, 에이전트는 적절할 때 LTM 관련 도구를 호출할 수 있다. 이 단계는 $\tau_k^{(1)}=\{e_t\}_{t=1}^{T_1}$를 만든다.

**2단계(방해 요소 아래 STM 제어).** 구성된 LTM $M_t$는 유지하지만 STM은 초기화한다. 이후 에이전트에게 방해 메시지, 즉 그럴듯한 대화 문맥처럼 보이지만 목표 질의와는 의도적으로 무관한 자연어 발화(질문 또는 짧은 문장)를 제시한다. 에이전트는 최종 답을 위해 이 메시지에 의존하지 말고 걸러내거나 무시해야 한다. 목표는 필터링·요약 같은 도구 기반 연산을 통해 능동적으로 STM을 제어하고, 잡음을 억제하며 유용한 정보를 보존하는 법을 배우는 것이다. 이 과정은 컨텍스트 필터링과 압축 능력을 강조하는 $\tau_k^{(2)}=\{e_t\}_{t=T_1+1}^{T_1+T_2}$를 이룬다.

**3단계(통합 추론 및 메모리 조정).** 마지막으로 에이전트는 정확한 추론과 효과적인 메모리 검색을 함께 요구하는 정식 질의 $q$를 받는다. $M_t$에서 관련 지식을 검색하고, $C_t$를 적절히 관리하며, 최종 답을 생성해야 한다. 이 단계는 LTM·STM 관리·과제 해결을 종단 간으로 조정하는 능력을 평가하는 $\tau_k^{(3)}=\{e_t\}_{t=T_1+T_2+1}^{T}$를 만든다.

세 구간은 완전 궤적을 이룬다.

$$\tau_k^{(q)}=(e_1,e_2,\ldots,e_T),\quad T=T_1+T_2+T_3.\tag{4}$$

이는 다음 단계별 GRPO 절차에서 정책 최적화에 쓴다. 과제 $B$개인 배치에서는 $K$개 독립 rollout의 모든 경험을 $E=\bigcup_{q=1}^{B}\bigcup_{k=1}^{K}\{e_t\mid e_t\in\tau_k^{(q)}\}$로 합치며, 크기는 $|E|=B\times K\times\bar T$이다. $\bar T$는 평균 궤적 길이다. 상세 rollout은 부록 A.3에 제시한다.

**3단계 교육과정의 일반성.** 이 구조는 QA 형식 감독에 묶이지 않는다. 지연된 결과 아래 메모리 결정의 효용을 평가하도록 정보 노출과 과제 실행을 시간적으로 분리하기만 하면 된다. 각 단계의 기능적 역할은 여러 도구 사용 환경으로 옮길 수 있다. 1단계(정보 획득)는 에이전트가 선택적으로 저장할 수 있는 사전 과제 문맥이면 되며, 환경 설명·검색 문서·이전 대화 이력일 수 있고 QA 근거 사실일 필요는 없다. 2단계(간섭과 컨텍스트 압박)는 부록 A.3에 상세히 적은 `DISTRACTOR_GEN`이 이미 합성하므로 데이터셋 주석을 요구하지 않는다. 3단계(과제 실행)는 앞선 저장·필터링 결정이 유용했는지를 지연 보상으로 판정하는 하류 목표를 제공한다. 이 교육과정은 QA식 사실 감독이 아니라 정보의 시점과 지연 공적 할당에 의존한다.

### 3.4 통합 관리를 위한 단계별 GRPO

장거리 과제 보상을 모든 단계의 메모리 결정과 연결하기 위해 단계별 GRPO 변형을 쓴다. 과제 $q$에 대해 병렬 rollout 집합을 $G_q=\{\tau_1^{(q)},\ldots,\tau_K^{(q)}\}$라 하자. 각 궤적은 종료 보상 $r_T^{(k,q)}=R(\tau_k^{(q)})$를 낸다. 종료 단계의 그룹 정규화 이점은 다음과 같다.

$$A_T^{(k,q)}=\frac{r_T^{(k,q)}-\mu_{G_q}}{\sigma_{G_q}+\epsilon}.\tag{5}$$

$\mu_{G_q}$와 $\sigma_{G_q}$는 $G_q$ 안 보상의 평균과 표준편차이고, $\epsilon$은 0으로 나누는 일을 막는다. 이 이점을 같은 궤적의 모든 선행 단계에 방송하여 $A_t^{(k,q)}=A_T^{(k,q)}$로 둔다. 이에 따라 1·2단계를 포함한 궤적 전체의 메모리·추론 행동이 일관된 학습 신호를 받는다. 즉 최종 과제 결과가 모든 중간 메모리 결정을 감독하여 이질적 단계 전반의 장거리 공적 할당을 가능하게 한다. 이점을 붙인 경험 집합은 $E=\bigcup_{q,k}\{(e_t,A_t^{(k,q)})\mid e_t\in\tau_k^{(q)},A_t=A_T^{(k,q)}\}$다.

GRPO에 따라 모든 경험에 대한 기대 목적함수를 최대화한다.

$$J(\theta)=\mathbb E_{(e_t,A_t)\sim E}[\rho_tA_t-\beta D_{KL}[\pi_\theta\Vert\pi_{ref}]],\tag{6}$$

여기서 중요도 비율 $\rho_t=\pi_\theta(a_t\mid s_t)/\pi_{\theta_{old}}(a_t\mid s_t)$는 새 정책에서 갱신 크기를 제어한다. $D_{KL}$은 현재 정책 $\pi_\theta$와 고정 참조 정책 $\pi_{ref}$ 사이의 KL 발산 벌점이고, $\beta$는 탐색과 학습 안정성의 균형을 맞추는 계수다.

### 3.5 보상 함수 설계

하류 과제 성능과 메모리 관리 품질을 모두 평가하는 복합 보상을 설계한다. 전체 궤적 수준 보상은 다음과 같다.

$$R(\tau)=\mathbf w^\top\mathbf R+P_{penalty}.\tag{7}$$

여기서 $\mathbf w=[w_{task},w_{context},w_{memory}]^\top$는 조정 가능한 계수이고, $\mathbf R=[R_{task},R_{context},R_{memory}]^\top$는 과제 완료·컨텍스트 관리·LTM 관리 보상이다. 벌점 $P_{penalty}$는 컨텍스트 오버플로 또는 상호작용 한도 초과 같은 위반을 포착한다. 각 성분의 정확한 식은 부록 A.2에 제시한다.

**과제 완료 보상 $R_{task}$.** 이 항은 에이전트가 과제를 올바르게 풀었는지 평가하여 주 학습 신호를 제공한다. LLM 기반 심사자 $S_{judge}(A_{pred},A_q)\in[0,1]$로 스칼라 점수를 얻고, 답이 생성되지 않으면 선택적으로 벌점을 준다. 이 보상은 정확하고 완전한 과제 해결을 장려하며, 과제 목표와의 정렬을 보장하는 지배적 성분으로 유지한다.

**컨텍스트 관리 보상 $R_{context}$.** 이 성분은 활성 컨텍스트 $C_t$를 얼마나 효과적으로 제어하는지 평가한다. 토큰을 경제적으로 쓰게 하는 압축 효율, 오버플로를 피하기 위한 이른 요약 또는 필터링을 보상하는 예방 행동, 질의 관련 핵심 정보의 손실을 벌하는 정보 보존의 세 요소를 결합한다. 각 요소는 정규화되어 있어, 보상이 컨텍스트 효율과 본질 정보 보존 사이의 균형을 잡는다.

**메모리 관리 보상 $R_{memory}$.** 이 항은 LTM 연산을 평가한다. 고품질·재사용 가능으로 판정된 저장 항목의 비율로 측정하는 저장 품질, 메모리 노후화를 줄이는 의미 있는 갱신 또는 삭제를 보상하는 유지보수, 검색 기억과 질의 사이의 LLM 기반 점수로 계산하는 의미 관련성의 신호를 합산한다. 이 신호들은 선택적이고 가치 높은 메모리 구성과 시간에 따른 책임 있는 유지보수를 유도한다.

**벌점 $P_{penalty}$.** 최대 대화 라운드 수를 넘거나 컨텍스트 오버플로를 유발하는 바람직하지 않은 행동을 억제한다. 이러한 위반이 최종 궤적 보상을 상당히 줄이도록 벌점 계수를 정해, 안전하고 효율적인 메모리 관행을 유지하게 한다.

## 4. 실험

### 4.1 실험 설정

**데이터셋.** AgeMem을 종합 평가하기 위해 LLM 기반 에이전트 연구에서 널리 쓰이는 다섯 데이터셋, ALFWorld(Shridhar et al., 2020), SciWorld(Wang et al., 2022), PDDL(Chang et al., 2024), BabyAI(Chevalier-Boisvert et al., 2018), HotpotQA(Yang et al., 2018)를 선택했다. 이 데이터셋들은 체화 행동, 게임 기반 추론, 지식 집약 질의응답을 포괄하여 다양한 평가 환경을 제공한다. HotpotQA는 질문과 근거 사실을 모두 포함해 1단계 문맥 정보를 자동으로 제공하므로, AgeMem은 HotpotQA 학습 집합에서만 RL 미세 조정을 한 뒤 모든 데이터셋에서 직접 평가했다. 상세 데이터셋 통계는 부록 C.1에 제시한다.

**평가 지표.** 주 과제 완료 지표로 ALFWorld·SciWorld·BabyAI에는 Success Rate(SR), PDDL에는 Progress Rate(PR), HotpotQA에는 LLM-as-a-Judge(J)를 사용한다. 또한 지식 추론 중 저장한 LTM의 품질을 평가하기 위해 LLM 기반 평가자로 Memory Quality(MQ)를 측정한다. LLM 기반 평가 프롬프트는 부록 C.2에 제시한다.

**기준선 및 LLM 백본.** AgeMem을 대표적 에이전트 LTM 시스템 네 가지, LangMem(LangChain Team, 2025), A-Mem(Xu et al., 2025), Mem0(Chhikara et al., 2025), Mem0g(Mem0이 공식 제공한 그래프 기반 변형)와 비교한다. RL 학습의 효과를 보이기 위해 RL 미세 조정을 하지 않은 AgeMem-noRL도 넣는다. STM 절제에서는 STM 도구를 RAG와 비교한다. 기본 에이전트 모델은 Qwen2.5-7B-Instruct와 Qwen3-4B-Instruct다. 에이전트는 Agentscope(Gao et al., 2025a)로 구축하고, AgeMem은 Trinity(Pan et al., 2025a)로 미세 조정했다. 추가 기준선 설정은 부록 C.3에 적는다.

## 5. 결론

본 논문은 LLM 기반 에이전트가 학습 가능한 도구 기반 행동으로 LTM과 STM을 공동 제어하게 하는 통합 메모리 관리 프레임워크 AgeMem을 제안했다. 메모리 연산을 에이전트 정책에 직접 통합하고 점진적 RL로 학습함으로써, 휴리스틱 메모리 파이프라인을 종단 간 최적화 해법으로 바꾼다. 여러 장기 시간 범위 벤치마크에서 AgeMem은 효율적인 컨텍스트 사용을 유지하면서 과제 성능과 메모리 품질을 모두 높였다. 이는 확장 가능하고 적응적인 장기 추론 LLM 에이전트를 위해 통합되고 에이전트 중심인 메모리 정책이 중요함을 보여 준다.

## 한계

AgeMem은 여러 설정에서 강한 성능을 보였지만 확장 여지가 있다. 현재 구현은 고정된 메모리 관리 도구 집합을 사용한다. 이는 명확하고 효과적인 추상화이지만, 이후 더 세밀한 제어를 지원하도록 확장할 수 있다. 또한 다섯 대표 장기 벤치마크와 도메인 간 zero-shot 전이를 평가했으나, 이 설정들은 개방형 실제 배포와 비교하면 여전히 통제되어 있다. 지속적 장기 대화와 실제 사용자 상호작용에서 평가하는 일은 중요한 다음 단계다. 마지막으로 현재 학습은 HotpotQA를 3단계 궤적의 출처로 사용한다. 더 풍부한 상호작용 구조를 가진 다른 데이터 원천으로 교육과정을 확장하면 프레임워크의 적용 가능성을 더 넓힐 수 있다.

## 부록 A. AgeMem의 상세 설계와 구현

이 부록은 지면 제약 때문에 본문에서 생략한 전체 기술 세부를 제공한다. 먼저 각 메모리 관리 도구의 정확한 정의와 의사 정식화를 제시하고(A.1), 학습에 쓴 보상 성분의 구현 가능한 식을 제시하며(A.2), 마지막으로 완전한 알고리즘 명세를 제공한다(A.3).

### A.1 메모리 관리 도구

AgeMem은 에이전트가 행동 $a_t$의 일부로 호출할 수 있는 작은 구조화 도구 집합을 제공한다. 각 도구는 STM $C_t$, LTM 저장소 $M_t$, 또는 둘 모두를 변환하는 결정적 또는 확률적 함수로 구현한다. 외부 휴리스틱이나 미리 정한 일정에 의존하는 전통 메모리 시스템과 달리, AgeMem은 이 도구들을 에이전트 행동 공간에 직접 넣어 모델이 강화학습으로 각 도구를 언제 어떻게 쓸지 학습하게 한다.

**표기.** 시점 $t$의 LTM 저장소는 $M_t=\{m_i\}_{i=1}^{|M_t|}$이며, 각 기억 $m_i$는 콘텐츠 문자열과 선택적 메타데이터를 담는다. STM은 메시지 목록 $C_t=[u_1,u_2,\ldots,u_{n_t}]$이다. $enc(\cdot)$는 조밀 임베딩을 반환하는 텍스트 인코더이며, 프레임워크 전체에서 의미 일치에 코사인 유사도를 사용한다.

**`RETRIEVE`.** 이 연산은 의미 유사도를 기준으로 LTM에서 관련 정보를 꺼내 활성 컨텍스트에서 추론할 수 있게 한다. 질의 $q$와 가장 유사한 상위 $k$개 기억을 반환한다.

$$RETRIEVE(q,k)=TopK(M_t,sim(q,m_i),k),\tag{8}$$

$$sim(q,m_i)=\frac{enc(q)^\top enc(m_i)}{\|enc(q)\|\|enc(m_i)\|}.\tag{9}$$

검색된 기억은 이후 $C_t$에 삽입된다. $k$는 검색할 기억 수를 제어하며, 실험에서는 관련성과 컨텍스트 크기의 균형을 위해 보통 3~5로 설정했다.

**`ADD`.** 새 정보를 향후 사용하도록 LTM에 저장한다. 새 기억은 다음과 같이 만든다.

$$m_{new}=(c,enc(c),metadata),\tag{10}$$

여기서 $c$는 저장할 콘텐츠, $enc(c)$는 임베딩 벡터이고 `metadata`에는 타임스탬프·출처 정보·선택 태그가 들어간다. 이어 저장소를 갱신한다.

$$M_{t+1}=M_t\cup\{m_{new}\}.\tag{11}$$

보상 함수는 고품질이고 재사용 가능한 지식을 저장하도록 장려하며, 중복되거나 무관한 항목에는 불이익을 준다.

**`UPDATE`와 `DELETE`.** 유지보수 연산은 장기 저장소가 최신이고 관련된 상태로 남게 한다. 새 정보가 이전 지식을 대체하거나 보완할 때 `UPDATE`는 기존 기억 $m_i$를 다음처럼 수정한다.

$$m_i\leftarrow(c',enc(c'),metadata').\tag{12}$$

$c'$는 갱신 콘텐츠이고 `metadata'`에는 수정 시각이 반영된다. `DELETE`는 더는 유효하지 않거나 잘못된 기억을 제거한다.

$$M_{t+1}=M_t\setminus\{m_i\}.\tag{13}$$

이 두 연산은 정보가 오래되거나 초기 오류를 바로잡아야 하는 장기 과제에서 특히 중요하다. 보상 함수는 시간이 지날수록 메모리 품질을 높이는 의미 있는 갱신과 삭제를 장려한다.

**`SUMMARY`.** 이 연산은 본질 정보를 보존하면서 컨텍스트 오버플로를 막기 위해 STM의 대화 이력을 압축한다. 컨텍스트 인덱스 부분집합 $s$가 주어지면,

$$C_t'=C_t\setminus\{u_i\mid i\in s\}\cup\{Summarize(\{u_i\}_{i\in s})\}.\tag{14}$$

여기서 `Summarize(·)`는 요약 시스템 프롬프트를 따른 LLM으로 구현한다. 에이전트는 `span` 인수로 요약 메시지를 지정하며, `all`은 시스템 메시지를 제외한 모든 메시지, `N`은 마지막 $N$개 메시지를 뜻한다. 요약 프롬프트는 주제·행동·결과·미해결 문제를 식별하고, 인사·군더더기·중복 표현은 제외한 명확하고 사실적인 요약을 생성하게 한다. 요약이 원래 대화를 대체하므로 본질 정보가 손실되지 않아야 한다. 에이전트는 정보 보존과 효율의 균형을 맞추며 오버플로 전에 요약을 선제 호출하도록 학습한다.

**`FILTER`.** 이 연산은 의미 유사도에 따라 STM에서 무관하거나 중복된 메시지를 제거한다. 주어진 기준 $c$와의 유사도가 임계값 $\theta_f$ 이상인 메시지를 제거한다.

$$C_t'=\{u_i\in C_t\mid sim(c,u_i)<\theta_f\}.\tag{15}$$

모든 실험에서 기본값은 $\theta_f=0.6$이다. 기준 $c$는 에이전트가 지정할 수 있고(예: 유지할 콘텐츠를 설명), 현재 과제 문맥에서 자동으로 유도할 수도 있다. 이 도구는 방해 요소를 넣어 에이전트의 무관 정보 필터링 능력을 시험하는 2단계에서 특히 유용하다.

**구조화 행동으로서의 도구 호출.** 각 도구는 함수명과 필수 인수를 명시한 스키마로 제공한다. 정책은 텍스트 생성용 언어 토큰 또는 메모리 연산용 구조화 도구 호출을 출력한다. 시스템 프롬프트는 모든 과제를 `<think>...</think>` 블록으로 시작하게 하며, 그 안에서 추론·다음 단계 계획·도구 호출 또는 최종 답 여부를 결정한다. 도구를 쓰면 그 뒤에 하나 이상의 호출을 JSON 배열로 담은 `<tool_call>...</tool_call>`을, 최종 출력 준비가 됐으면 완전한 응답을 담은 `<answer>...</answer>`를 둔다. 각 `<think>` 블록 뒤에는 둘 중 정확히 하나만 있어야 하며, 필요할 만큼 `<think> → <tool_call>`을 반복한 뒤 `<think> → <answer>`로 끝낸다. 모든 추론은 `<think>` 태그, 모든 도구 사용은 하나의 `<tool_call>` 태그, 최종 해법은 `<answer>` 태그 안에 있어야 하고 그 밖에는 텍스트가 없어야 한다. 이 형식은 RL 중 신뢰할 수 있는 파싱과 보상 계산을 보장하고, 한 추론 단계에서 복수 메모리 연산을 조정하게 한다.

> 그림 6. 대화 컨텍스트 관리를 위한 STM 도구. `Summary_context(span)`은 대화 라운드를 요약해 토큰을 줄이고, `Filter_context(criteria)`는 무관하거나 오래된 콘텐츠를 걸러내며, `Retrieve_memory(query, top_k, metadata_filter)`는 관련 기억을 현재 컨텍스트에 더한다.  
> 그림 7. 지속 저장을 위한 LTM 도구. `Add_memory(content, metadata, memory_type)`, `Update_memory(memory_id, content, metadata)`, `Delete_memory(memory_id, confirmation)`은 대화 전반의 장기 정보를 각각 추가·갱신·삭제한다.

### A.2 보상 함수 설계

달리 언급하지 않는 한 모든 성분 점수는 안정적인 가중을 위해 $[0,1]$로 정규화한다. 전체 궤적 보상은 $R(\tau)=\mathbf w^\top\mathbf R+P_{penalty}$다. 최종 답이 있으면 $R_{task}=S_{judge}(A_{pred},A_q)$이고, 답이 없으면 기본 $P_{no\text{-}answer}=-1.0$을 준다.

컨텍스트 보상은 세 성분의 가중합이다.

$$R_{context}=\sum_{i=1}^3\alpha_iR_i,\quad R_i\in\{R_{compression},R_{preventive},R_{preservation}\},\quad\sum_i\alpha_i=1,\tag{18}$$

기본적으로 $\alpha_i=1/3$이다. 최종 답 생성 시 사용 토큰 $T_{used}$와 허용 예산 $T_{max}$로 압축 효율을 계산한다.

$$R_{compression}=\max(0,1-T_{used}/T_{max}).\tag{19}$$

토큰 한도 전에 컨텍스트 축소 도구를 호출하면 $R_{preventive}=1$이고, 그렇지 않으면 0이다. 질의에서 개체명·시간·공간 표현 같은 핵심 토큰 또는 구절 집합 $K_q$를 뽑아, 답 생성 시 원문 또는 보존 요약에 남아 있으면 $R_{preservation}=1$로 둔다.

메모리 보상은 저장 품질·유지보수·의미 관련성의 가중합이다.

$$R_{memory}=\sum_{j=1}^3\beta_jR_j,\quad R_j\in\{R_{storage},R_{maintenance},R_{relevance}\},\quad\sum_j\beta_j=1.\tag{22}$$

기본적으로 $\beta_j=1/3$이다. 1단계에서 전체 $N_{total}$개 중 고품질로 판정된 저장 기억이 $N_{high\_quality}$개이면 $R_{storage}=N_{high\_quality}/\max(1,N_{total})$이다. 이는 가치 있는 정보를 저장하되 중복·저품질 기억 축적을 막는다. `UPDATE` 또는 `DELETE`를 수행하면 $R_{maintenance}=1$이다. 검색 기억 집합 $R$와 질의 $q$의 LLM 기반 의미 관련성 점수 $S_{LLM}(R,q)\in[0,1]$를 $R_{relevance}=S_{LLM}(R,q)$로 둔다. 벌점은 라운드 초과와 오버플로에 대해 $P_{rounds}=-1$, $P_{overflow}=-0.5$를 기본값으로 쓴다.
