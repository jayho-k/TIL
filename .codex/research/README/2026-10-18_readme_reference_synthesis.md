# 면접관이 탐색할 수 있는 TIL README 구성 조사

조사일: 2026-10-18. 공개 웹 문서와 현재 로컬 저장소를 확인했다.
목표: 저장소의 성격과 읽을 만한 기록을 짧게 안내한다.
검토 대상은 저장소 README이며, 개인 프로필 README나 경력기술서와 구분한다.

## 결론

저장소의 특징을 담은 짧은 소개 → 학습 방향 → 분야별 링크를 기본안으로 추천한다.
소개와 주제별 탐색은 아래 사례에서 직접 관찰되는 구성이다.
전체 글 목록을 분야별 폴더 표로 줄이는 것은 사용자의 간결성 요구에 따른 편집 판단이다.
이 구성이 면접 합격률을 높인다는 실험적 근거는 확인하지 못했다.

### 특징과 방향 보강

사용자는 재검토 과정에서 TIL의 특징과 지향하는 방향도 필요하다고 명시했다.
‘주요 기록’ 선정 근거 부족을 수정하며 소개와 폴더 표만 남긴 초안은 이 요구를 충분히 설명하지 못했다.
소개에는 관찰한 기록의 성격을, 학습 방향에는 앞으로 지향할 기준을 담는다.

- 내부 동작 분석: `CS/language/Python/method/List내부동작/List 내부구조.md`에서 구조체와 내부 구조를 설명한다.
- 구현 실습: `AI/agent_streaming/README.md`에서 스트리밍 구현과 실행·검증 방법을 안내한다.
- 적용 제약 분석: `AI/mem0/text/02_Mem0_동작원리_및_운영상_제약.md`에서 조사 기준과 적용 시 고려사항을 설명한다.

위 파일은 소개 문구를 뒷받침하는 사례이며, 전체 기록을 대표하는 상위 세 글로 선정한 것이 아니다.
‘동작 원리 이해·실습으로 확인·선택의 근거 정리’는 이 관찰과 사용자 요구를 반영한 방향 제안이다.
모든 기존 노트가 이미 이 기준을 충족한다고 주장하지 않는다.

### 초안 재검토에 따른 정정

최초 답변에서 ‘주요 기록 3개’를 가장 적절한 구성이라고 단정했다.
그러나 조사한 TIL 사례에서 직접 확인한 패턴은 짧은 소개·작성 규칙·주제별 인덱스이며,
임의로 고른 대표 글 3개를 상단에 배치하는 공통 패턴은 확인하지 않았다.
S2의 대표 프로젝트 안내를 TIL 내부 대표 글 선정으로 확장한 것은 작성자의 추론이었다.
전체 기록을 비교하거나 사용자에게 강조할 주제를 확인하지 않고 Agent·Mem0·Kafka를 선정한 것도
이 세 글의 대표성을 뒷받침하지 못한다. 초안에서 해당 섹션을 제거했다.

## 여러 자료를 교차해서 얻은 판단

### 처음 방문한 사람이 저장소의 성격을 알 수 있어야 한다

- 근거: S1·S3의 가이드와 S4·S5·S7·S9의 도입부.
- 확신: 높음. 단, 소개를 정확히 두 문장으로 제한하는 것은 이 저장소의 간결성 요구에 맞춘 선택이다.
- 적용: 학습 개념과 실습을 기록한다는 문장, 다루는 범위를 설명하는 문장을 둔다.
- 의미: 독자가 학습 노트와 실습 코드를 어떤 맥락으로 읽을지 알 수 있다.

### 소개보다 실제 기록으로 이동하는 경로에 공간을 배정한다

- 근거: S5·S6·S8·S9의 주제별 링크, S2의 이해·탐색 용이성 권고.
- 확신: 탐색 경로는 사례에서 직접 확인된다. 특정 글 3개를 강조해야 한다는 근거는 확인되지 않았다.
- 적용: 전체 폴더 5개를 표로 안내한다.
- 의미: 관심 있는 독자는 상세 내용으로 바로 이동할 수 있다.

### 사례에서 반복된 요소라도 사용 목적과 맞는지 판단한다

- 관찰: S5·S6·S8·S9는 많은 노트를 README에 나열한다. S4는 소개 자체가 매우 짧다.
- 긴 인덱스는 이미 주제를 아는 독자의 검색·재방문에 유용하지만, 전체 길이를 늘린다.
- 해석: 서로 다른 독자와 운영 목적 때문에 구성도 다르다. 긴 README가 잘못되었다고 결론 내리지 않는다.
- 적용: 사용자의 간결성 요구에 따라 전체 노트 목록은 넣지 않는다.

## 현재 저장소에서 확인한 내용

- 루트 README는 완전히 빈 파일은 아니며 `Today I learned` 한 줄이 있다.
- `.codex/MAP.md`와 실제 폴더를 대조했다. 주요 분류는 AI, CS, Server, Web, PS다.
- 대표 후보의 본문과 Agent 스트리밍 부하 테스트 보고서를 읽었다. 전체 노트를 정확성 검수한 것은 아니다.
- 스트리밍 README는 현재 EventSourceResponse 구현과 연결 종료·오류 처리·검증 방법을 설명한다.
- 스트리밍 부하 보고서는 과거 fake Agent smoke 결과와 현재 구현의 검증 범위를 구분한다.
  따라서 처리량 개선 수치나 실제 서비스 운영 성과를 루트 README에서 주장하지 않는다.
- Mem0 노트에는 조사일 2026-07-12와 확인한 OSS commit이 있다.
  해당 기준에서의 분석으로 안내하며 현재 최신 버전의 사실이라고 재검증한 것은 아니다.
- Kafka Consumer 노트는 poll·commit, 구성요소, 메시지 처리 흐름을 다룬다.
  운영 최적화 성과나 해당 기술의 완전한 숙련도를 주장하지 않는다.
- Python GC와 vLLM 노트도 표본으로 읽었다. 대표 기록 선정은 품질 순위나 전수 평가가 아니다.

## 초안의 편집 기준

- ‘주요 기록’ 섹션은 두지 않는다. 이번 조사만으로 특정 세 글의 대표성을 설명할 수 없다.
- 특징을 설명하는 소개, 학습 방향, 분야별 표를 기본 구성으로 사용한다.
- 특정 글을 강조하는 구성은 추후 별도 목적과 선정 기준이 생겼을 때 검토할 선택지다.
- 기술 배지, 방문자 수, 잔디 통계, 다짐, 상세한 내부 초안 작성 절차는 넣지 않는다.
  이는 해당 요소들이 채용에 해롭다는 연구 결과가 아니라 이 README의 공간 우선순위 판단이다.
- 작성 규칙은 별도 항목으로 추가하지 않는다. 실제 기록에 출처와 버전을 남기는 것이 더 구체적이다.
- 라이선스·기여 정책은 이번 문구 작성에서 새로 결정하지 않는다.

## 남은 불확실성

- 지원 직무와 면접에서 강조할 경험이 아직 특정되지 않았다. 특정 글을 임의로 우선하지 않는다.
- 이 표본들은 접근 가능한 공개 사례를 목적에 맞게 고른 것으로, 전체 TIL 저장소의 통계 표본이 아니다.
- 최적 글자 수, 배지 유무, 대표 글 개수에 따른 채용 효과는 확인한 자료로 입증할 수 없다.
- README가 짧더라도 연결된 노트의 정확성과 설명 가능성이 별도로 중요하다.
