# OSS: 새 Memory 알고리즘으로 마이그레이션

> 원문: 사용자가 제공한 Mem0 문서 `Open Source: Migrating to the New Memory Algorithm`  
> 원문 제공일: 2026-07-18  
> 문서 인덱스: <https://docs.mem0.ai/llms.txt>

> ADD-only extraction, hybrid search, entity linking을 사용하는 self-hosted Mem0 사용자를 위한 upgrade 안내서

> 경고: 이 release에는 이름이 바뀐 parameter, 제거된 parameter, 변경된 기본값, 근본적으로 달라진 extraction model이 포함된다. upgrade 전에 이 안내서를 읽는다.

## 개요

새 release는 Python/TypeScript의 SDK surface를 정리하면서 extraction과 retrieval을 모두 재설계했다.

- **Extraction:** single-pass ADD-only(LLM 1회, 자동 UPDATE/DELETE 없음)
- **Retrieval:** multi-signal hybrid search(semantic + BM25 keyword + entity matching)
- **Entity linking:** entity를 자동 추출하고 memory 간 연결
- **SDK 정리:** deprecated parameter 제거, naming convention 표준화
- **Platform API와 정렬:** OSS/Platform 모두 `add()`·`delete_all()`은 top-level kwargs, `search()`·`get_all()`은 `filters` 내부 entity ID를 사용

이 변경으로 LoCoMo는 **20점 상승**(71.4 → 91.6), LongMemEval은 **26점 상승**(67.8 → 93.4)했고 extraction latency는 약 절반으로 줄었다.

## 호환성이 깨지는 변경

### Python Open Source

| 변경 | 이전 | 이후 | 마이그레이션 |
| --- | --- | --- | --- |
| `search()`/`get_all()` entity ID | top-level `user_id="..."` | `filters` dict 내부 | `m.search("q", filters={"user_id": "..."})`; top-level은 `ValueError` |
| `top_k` 기본값 | `100` | `20` | 이전 동작은 `top_k=100` |
| `threshold` 기본값 | `None`(filter 없음) | `0.1`(낮은 관련성 제거) | 이전 동작은 `threshold=0.0` |

| `rerank` 기본값 | `True` | `False` | 이전 동작은 `rerank=True` |
| Entity ID | 임의 문자열 | trim 후 빈 값/공백만 있으면 거부 | 내부 공백 없는 비어 있지 않은 ID 전달 |
| `add()`의 `messages` | `None` 가능 | `str`/`dict`/`list[dict]`만 가능 | 항상 유효한 message 전달 |

| Custom extraction prompt | `custom_fact_extraction_prompt` | `custom_instructions` | config rename |
| Custom update prompt | `custom_update_memory_prompt` | deprecated | `custom_instructions` 사용 |
| Graph memory | `enable_graph` + `graph_store` | 제거 | external graph store 지원 제거 |
| Qdrant client | `>=1.9.1` | `>=1.12.0` | dependency update |
| Upstash client | `>=0.1.0` | `>=0.6.0` | dependency update |

| --- | --- | --- | --- |

| SDK | 주요 변경 |
| --- | --- |
| Python Client | `MemoryClient(api_key)`만 사용; `org_id`, `project_id` 제거. typed option class 또는 `**kwargs` 사용 가능. `api_version`, `output_format`, `async_mode`, `filter_memories`, `keyword_search`, `force_add_only`, `batch_size`, `immutable`, `includes`, `excludes`, `enable_graph`, `org_name`, `project_name` 제거. |

## 단계별 마이그레이션

### 1. 설치 갱신

```bash
# 기본 upgrade
pip install --upgrade mem0ai

# hybrid search + entity extraction(권장)
pip install --upgrade "mem0ai[nlp]"
python -m spacy download en_core_web_sm

# Qdrant: BM25 keyword search 활성화
pip install fastembed

# TypeScript
npm install mem0ai@latest
```

`[nlp]` extra는 entity extraction과 keyword lemmatization용 spaCy를 설치한다. 없으면 semantic-only search로 fallback한다. 이 extra는 Python 3.10~3.12만 지원한다. Python 3.13에서는 spaCy의 `blis`/`thinc` prebuilt wheel이 없어 build에 실패한다. base `mem0ai`는 지원 Python version에서 동작하며 제약은 NLP extra에만 적용된다.

Qdrant는 같은 collection에 dense vector와 BM25 sparse vector를 함께 encoding하기 위해 `fastembed`가 필요하다. 없으면 BM25는 조용히 비활성화되고 첫 search에서 warning을 남긴 뒤 semantic-only로 fallback한다. 다른 vector store는 native full-text 기능을 사용하므로 필요 없다.

### 2. Config 갱신

```python
# 이전
config = {
    "custom_fact_extraction_prompt": "Focus on user preferences",
    "custom_update_memory_prompt": "Be concise when updating",
    "graph_store": {"provider": "neo4j", "config": {"url": "...", "username": "...", "password": "..."}},
    "enable_graph": True,
}

# 이후
config = {
    "custom_instructions": "Focus on user preferences",
    # custom_update_memory_prompt, enable_graph, graph_store 제거
}
```

```typescript
// 이전: customPrompt, enableGraph, graphStore
// 이후
const config = {
  customInstructions: "Focus on user preferences",
};
```

### 3. Search 호출 갱신

```python
# 이전
results = m.search("what meetings did I attend?", user_id="alice", top_k=20)

# 이후: entity ID는 filters 내부
results = m.search(
    "what meetings did I attend?",
    filters={"user_id": "alice"},
    top_k=20,
    threshold=0.1,
    rerank=False,
)
```

`search()`/`get_all()`에 `user_id`, `agent_id`, `run_id`를 top-level kwarg로 전달하면 `ValueError`가 난다. 반면 `add()`와 `delete_all()`은 top-level entity ID를 계속 받는다.

```typescript
// 이전
const results = await m.search("what meetings did I attend?", { userId: "alice", limit: 20 });

// 이후
const results = await m.search("what meetings did I attend?", {
  filters: { userId: "alice" }, topK: 20
});
```

Client SDK도 Python은 `SearchMemoryOptions(filters={"user_id": "alice"}, top_k=20)`, TypeScript는 `filters: { userId: "alice" }, topK: 20`을 사용한다.

### 4. Add 호출 갱신

```python
# 이전에는 ADD/UPDATE/DELETE event를 모두 처리했다.
# 이후에는 ADD만 처리한다.
result = m.add("I love hiking and my dog's name is Max", user_id="alice")
for item in result["results"]:
    print("New memory:", item["memory"])
```

Python Client는 `async_mode`, `output_format`이 제거되었으며 다음처럼 쓴다.

```python
from mem0.client.types import AddMemoryOptions
client.add(messages, options=AddMemoryOptions(user_id="alice"))
# 또는 client.add(messages, user_id="alice")
```

TypeScript Client는 camelCase를 사용한다.

```typescript
await client.add(messages, { userId: "alice" });
```

ADD-only model에서는 정보가 바뀌어도 새 fact가 이전 fact 옆에 추가된다. retrieval이 더 관련성 높고 현재인 정보를 위로 올려 준다.

### 5. Vector store dependency 갱신

```bash
pip install "qdrant-client>=1.12.0"
pip install "upstash-vector>=0.6.0"
```

### 6. Entity store 설정

새 algorithm은 첫 사용 시 `{your_collection}_entities` parallel collection을 자동 생성한다. 수동 setup은 필요 없지만 vector store credential에 collection 생성 권한이 있어야 한다. managed DB의 권한이 제한되어 있다면 main collection과 같은 embedding dimension으로 `{collection_name}_entities`를 미리 만든다.

## Graph Memory: built-in으로 변경

외부 graph **store** 지원은 OSS SDK에서 제거되고, external dependency 없이 native로 동작하는 **built-in graph memory**(entity linking)로 대체됐다.

제거된 항목:

- `enable_graph` / `enableGraph`
- Neo4j, Memgraph, Kuzu, Apache AGE, Neptune용 `graph_store` / `graphStore`
- external graph store code path 약 4,000줄

대신 `add()` pipeline에서 모든 memory의 proper noun, quoted text, compound noun phrase entity를 추출해 `{collection}_entities`에 저장한다. entity를 공유하는 memory는 연결되고, search 시 query entity와 매칭해 연결된 memory의 score를 boost한다. 이 boost는 결과의 combined `score`에 합쳐진다.

따라서 config에서 graph flag/block을 제거하고, Mem0만을 위해 설치한 external graph driver도 삭제한다. 다음 `add()`에서 built-in graph memory가 자동 활성화되므로 data migration은 필요 없다.

> 경고: 과거 external graph store가 채우던 search result의 `relations` field는 더 이상 반환되지 않는다. entity 연결은 직접 traverse 가능한 graph가 아니라 retrieval ranking에만 적용된다.

## 새 알고리즘 동작 방식

### Extraction: Single-Pass ADD-Only

```text
입력 대화
  → 관련 기존 memory 상위 10개 조회(dedup context)
  → LLM 1회: 모든 distinct 새 fact 추출
  → 추출 memory batch embedding
  → hash 기반 deduplication(MD5, exact duplicate 방지)
  → vector store에 batch insert
  → entity extraction + linking
```

이전 algorithm은 candidate fact 추출 LLM 호출과 기존 memory에 대한 ADD/UPDATE/DELETE 결정 LLM 호출, 총 2회를 사용했다. 새 algorithm은 오직 add만 하는 1회 호출로 통합해 model이 state diff가 아닌 입력 이해에 집중하게 한다.

### Retrieval: Multi-Signal Hybrid Search

```text
Query
  → 전처리(keyword lemmatization, entity extraction)
  → 병렬 scoring
      1. semantic search(vector similarity)
      2. BM25 keyword search(normalized term matching)
      3. entity matching(entity graph boost)
  → score fusion → Top-K 선택
```

세 signal은 하나의 combined `score`로 normalize·fusion된다. 사용 가능한 runtime feature에 따라 semantic-only, semantic+BM25, 세 signal 모두로 동작한다. **BM25는 recall expander가 아니라 boost signal이다.** Candidate는 semantic search 결과만이며 BM25/entity는 새 candidate를 추가하지 않고 순위만 올린다.

## Vector store 호환성

15개 지원 vector store에는 다음 capability가 추가됐다.

| Capability | 목적 | 미지원 시 fallback |
| --- | --- | --- |
| `keyword_search()` | BM25/full-text keyword matching | semantic-only search |
| `search_batch()` | entity matching batch search | sequential search |

Qdrant는 같은 collection에서 sparse(BM25) vector와 dense vector를 함께 사용하며 `fastembed`가 필요하다. 나머지 store는 native full-text `keyword_search()`를 사용한다.

## Graceful degradation

| 누락 dependency | 영향 | Search 동작 |
| --- | --- | --- |
| spaCy (`mem0ai[nlp]`) | entity extraction, BM25 lemmatization 없음 | semantic-only |
| `fastembed`(Qdrant) | BM25 keyword search 없음 | semantic + entity |
| Entity store | entity boosting 없음 | semantic + BM25 |

언제나 semantic search는 제공되며 hybrid feature는 가능할 때 그 위에 추가된다.

## 제거·이름 변경 parameter 요약

- **Python Client:** constructor `org_id`, `project_id`; 모든 method의 `api_version`, `output_format`, `async_mode`, `org_name`, `project_name`; `add()`의 `enable_graph`, `immutable`, `filter_memories`, `batch_size`, `force_add_only`, `includes`, `excludes`, `keyword_search`; `search()`/`get_all()`의 `enable_graph` 제거.
- **TypeScript Client:** `organizationId`, `projectId`, `organizationName`, `projectName`, `OutputFormat`, `API_VERSION` 및 위와 대응하는 camelCase parameter 제거.
- **Python OSS:** `custom_fact_extraction_prompt` → `custom_instructions`; `custom_update_memory_prompt` deprecated; `enable_graph`/`graph_store` 제거.
- **TypeScript OSS:** `customPrompt` → `customInstructions`; `enableGraph`/`graphStore` 제거; `limit` → `topK`.

## 일반 문제

### TypeScript의 `limit` 오류

`limit`은 `topK`로 이름이 바뀌었다.

```typescript
const results = await m.search("query", { filters: { userId: "alice" }, topK: 20 });
```

### TypeScript Client에서 snake_case가 동작하지 않음

TypeScript Client parameter는 모두 camelCase다.

```typescript
await client.search("query", { filters: { userId: "alice" }, topK: 20 });
```

### `ValueError: Top-level entity parameters not supported in search() / get_all()`

```python
# 이전
results = m.search("query", user_id="alice", top_k=20)
# 이후
results = m.search("query", filters={"user_id": "alice"}, top_k=20)
```

### Search 결과가 이전보다 적음

기본 `threshold`가 `None`에서 `0.1`로 바뀌었다. 이전 동작을 복원하려면 다음을 사용한다.

```python
results = m.search("query", filters={"user_id": "alice"}, threshold=0.0)
```

### spaCy model을 찾을 수 없음

```bash
python -m spacy download en_core_web_sm
pip install "mem0ai[nlp]"
```

### Entity store collection 생성 실패

`{collection_name}_entities`를 자동 생성할 권한이 없으면 main collection과 같은 embedding dimension으로 미리 생성한다.

### Score가 이전과 다름

top-level `score` 범위는 여전히 `[0, 1]`이지만 V3에서는 계산식이 다르다. 결과 간 상대 순위는 비교 가능하지만 절대값은 바뀌므로 application의 hard threshold를 representative query로 다시 조정한다. raw cosine similarity가 필요하면 `vector_store.search(...)`로 unboosted vector query를 직접 실행한다.
