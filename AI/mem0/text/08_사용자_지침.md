# 사용자 지침

> 원문: 사용자가 제공한 Mem0 문서 `Custom Instructions`  
> 원문 제공일: 2026-07-18  
> 문서 인덱스: 전체 문서 인덱스는 <https://docs.mem0.ai/llms.txt>에서 가져올 수 있으며, 이 파일로 사용 가능한 모든 페이지를 찾을 수 있다.

> Mem0가 관심 있는 detail만 저장하도록 fact extraction을 조정한다.

사용자 지침으로 Mem0가 대화에서 정확히 어떤 fact를 기록할지 결정할 수 있다. 집중된 prompt를 정의하고 몇 가지 예시를 주면 Mem0는 사용 사례에 맞는 memory만 추가한다.

> **다음 상황에서 사용한다.**
>
> - 프로젝트에 일상 대화는 저장하지 않으면서 domain-specific fact(order number, customer information)가 필요하다.
> - 이미 memory schema가 명확하고 LLM이 그 schema를 따르길 원한다.
> - 관련 없는 detail이 long-term storage로 들어가지 못하게 해야 한다.

> 경고: 너무 넓은 prompt는 관련 없는 fact도 통과시킨다. 지침을 좁게 유지하고 실제 transcript로 시험한다.

> 참고: `custom_fact_extraction_prompt` parameter는 `custom_instructions`로 이름이 바뀌었다. 이전 version에서 upgrade한다면 config를 그에 맞게 고친다.

---

## 기능 구성

- **Prompt 지침:** 보존할 entity나 phrase를 설명한다. 구체적인 안내가 extractor를 집중시킨다.
- **Few-shot 예시:** model이 올바른 형식을 복사하도록 positive/negative case를 모두 보인다.
- **Structured output:** response는 `facts` array가 든 JSON을 반환하고 Mem0가 이를 개별 memory로 바꾼다.
- **LLM 설정:** Python은 `custom_instructions`, TypeScript는 `customInstructions`를 model setting과 나란히 둔다.

### Prompt 청사진

1. 허용할 fact type을 선언한다.
2. production message와 닮은 짧은 example을 포함한다.
3. 빈 출력(`[]`)과 값이 있는 출력을 모두 보인다.
4. `facts` key만 있는 JSON을 반환하도록 model에 상기시킨다.

## 설정

### 사용자 정의 prompt 작성

```python
custom_instructions = """
고객 지원 정보, 주문 detail, 사용자 정보가 포함된 entity만 추출하세요.
다음은 few-shot example입니다.

Input: 안녕하세요.
Output: {"facts" : []}

Input: 오늘 날씨가 좋네요.
Output: {"facts" : []}

Input: 제 주문 #12345가 아직 도착하지 않았어요.
Output: {"facts" : ["주문 #12345 미수령"]}

Input: 제 이름은 John Doe이고, 지난주에 산 신발을 반품하고 싶습니다.
Output: {"facts" : ["고객 이름: John Doe", "신발 반품 희망", "구매 시점: 지난주"]}

Input: 빨간색 중간 사이즈 셔츠를 주문했지만 파란색을 받았습니다.
Output: {"facts" : ["빨간색 중간 사이즈 셔츠 주문", "파란색 셔츠 수령"]}

위와 같이 fact와 고객 정보를 JSON 형식으로 반환하세요.
"""
```

```typescript
const customInstructions = `
고객 지원 정보, 주문 detail, 사용자 정보가 포함된 entity만 추출하세요.
다음은 few-shot example입니다.

Input: 안녕하세요.
Output: {"facts" : []}

Input: 오늘 날씨가 좋네요.
Output: {"facts" : []}

Input: 제 주문 #12345가 아직 도착하지 않았어요.
Output: {"facts" : ["주문 #12345 미수령"]}

Input: 제 이름은 John Doe이고, 지난주에 산 신발을 반품하고 싶습니다.
Output: {"facts" : ["고객 이름: John Doe", "신발 반품 희망", "구매 시점: 지난주"]}

Input: 빨간색 중간 사이즈 셔츠를 주문했지만 파란색을 받았습니다.
Output: {"facts" : ["빨간색 중간 사이즈 셔츠 주문", "파란색 셔츠 수령"]}

위와 같이 fact와 고객 정보를 JSON 형식으로 반환하세요.
`;
```

> 팁: example pair는 짧게 유지하고 실제 user message에서 보는 capitalization, punctuation, tone을 반영한다.

### Config에 prompt 불러오기

```python
from mem0 import Memory

config = {
    "llm": {
        "provider": "openai",
        "config": {
            "model": "gpt-5-mini",
            "temperature": 0.2,
            "max_tokens": 2000,
        }
    },
    "custom_instructions": custom_instructions,
}

m = Memory.from_config(config)
```

```typescript
import { Memory } from "mem0ai/oss";

const config = {
  llm: {
    provider: "openai",
    config: {
      apiKey: process.env.OPENAI_API_KEY ?? "",
      model: "gpt-4-turbo-preview",
      temperature: 0.2,
      maxTokens: 1500,
    },
  },
  customInstructions: customInstructions,
};

const memory = new Memory(config);
```

> 확인: 초기화한 뒤 알려진 example으로 빠르게 `add`를 호출하고, response가 별도의 fact로 분리되는지 확인한다.

## 동작 예시

### 예: 주문 지원 memory

```python
m.add("어제 laptop을 주문했고 주문 ID는 12345입니다.", user_id="alice")
```

```typescript
await memory.add("어제 laptop을 주문했고 주문 ID는 12345입니다.", { userId: "user123" });
```

```json
{
  "results": [
    {"memory": "Laptop 주문", "event": "ADD"},
    {"memory": "주문 ID: 12345", "event": "ADD"},
    {"memory": "어제 주문", "event": "ADD"}
  ]
}
```

> 확인: output에는 prompt에서 설명한 fact만 있고, 각각 별도의 memory entry로 저장된다.

### 예: 관련 없는 message 걸러내기

```python
m.add("저는 hiking을 좋아합니다.", user_id="alice")
```

```typescript
await memory.add("저는 hiking을 좋아합니다.", { userId: "user123" });
```

```json
{
  "results": []
}
```

> 팁: 비어 있는 `results`는 prompt가 목표 domain 밖의 content를 성공적으로 무시했음을 보여 준다.

## 기능이 동작하는지 검증하기

- rollout 중 모든 호출을 기록하고 `facts` array가 schema에 맞는지 확인한다.
- 관련 없는 message가 빈 `results` array를 반환하는지 확인한다.
- prompt를 편집할 때마다 regression sample을 실행하여 이전에 허용된 fact가 계속 통과하는지 확인한다.

---

## 모범 사례

1. **정확하게 쓴다.** 포착할 정확한 category 또는 field를 명시한다.
2. **Negative case를 보인다.** model이 건너뛰는 법을 배우도록 `[]`를 만들어야 하는 example을 포함한다.
3. **JSON을 엄격하게 유지한다.** downstream parsing을 단순하게 하도록 extra key를 피하고 `facts`만 반환한다.
4. **Prompt를 version 관리한다.** 빠른 rollback을 위해 version number로 prompt 변경을 추적한다.
5. **Output을 정기적으로 검토한다.** 저장된 memory를 표본 점검해 drift를 일찍 발견한다.
