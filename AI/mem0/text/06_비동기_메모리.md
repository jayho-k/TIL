# 비동기 메모리

> 원문: 사용자가 제공한 Mem0 문서 `Async Memory`  
> 원문 제공일: 2026-07-18  
> 문서 인덱스: 전체 문서 인덱스는 <https://docs.mem0.ai/llms.txt>에서 가져올 수 있으며, 이 파일로 사용 가능한 모든 페이지를 찾을 수 있다.

> event loop를 block하지 않고 Mem0 작업을 실행한다.

`AsyncMemory`는 Mem0 storage layer의 non-blocking interface를 제공한다. Python 애플리케이션은 async code에서 직접 memory를 add, search, 관리할 수 있다. FastAPI service, background worker 또는 `asyncio`에 의존하는 workflow 안에 Mem0를 넣을 때 사용한다.

> **다음 상황에서 사용한다.**
>
> - agent가 이미 async framework에서 실행되며 memory 호출을 자연스럽게 `await`해야 한다.
> - synchronous client를 거치지 않고 Mem0 storage를 로컬에 embed하고 싶다.
> - memory 작업을 다른 async API(OpenAI, HTTP 호출, database)와 섞을 계획이다.

> 경고: `AsyncMemory`는 실행 중인 event loop를 기대한다. runtime error를 피하려면 항상 `async def` 함수 안에서 호출하거나 `asyncio.run()` 같은 helper를 사용한다.

> 참고: TypeScript에서 작업 중이라면 Node SDK(`mem0ai/oss`)의 OSS `Memory` class도 완전히 async다. 모든 method는 `Promise`를 반환하며 `await`해야 한다. Python의 `AsyncMemory`는 FastAPI 같은 Python async framework에서 같은 목적을 수행한다. 두 runtime 모두 await된 memory 작업을 지원하므로 언어에 맞는 SDK를 선택한다.

## 기능 구성

- **직접 storage 접근:** `AsyncMemory`는 synchronous client와 같은 backend와 통신하되, 낮은 latency를 위해 모든 것을 process 내부에서 유지한다.
- **Method parity:** 각 memory 작업(`add`, `search`, `get_all`, `delete` 등)은 synchronous API를 그대로 반영하므로 같은 payload shape를 재사용할 수 있다.
- **동시 실행:** non-blocking I/O로 `asyncio.gather`를 사용해 여러 memory task를 schedule할 수 있다.
- **Scope 기반 정리:** `user_id`, `agent_id`, `run_id`를 계속 사용해 session과 agent별로 memory를 분리한다.

### Async method parity

| 작업 | Async signature | 참고 |
| --- | --- | --- |
| Memory 생성 | `await memory.add(...)` | synchronous `Memory.add`와 같은 argument |
| Memory 검색 | `await memory.search(...)` | 동일한 shape의 `results`가 있는 dict 반환 |
| Memory 목록 | `await memory.get_all(...)` | `user_id`, `agent_id`, `run_id`로 filter |
| Memory 조회 | `await memory.get(memory_id=...)` | ID가 잘못되면 `ValueError` 발생 |
| Memory 수정 | `await memory.update(memory_id=..., text=...)` | 부분 update 허용 |
| Memory 삭제 | `await memory.delete(memory_id=...)` | confirmation payload 반환 |
| 일괄 삭제 | `await memory.delete_all(...)` | scope filter를 하나 이상 요구 |
| History | `await memory.history(memory_id=...)` | 감사를 위한 change log 조회 |

## 설정

### Client 초기화

```python
import asyncio
from mem0 import AsyncMemory

# 기본 설정
memory = AsyncMemory()

# 사용자 정의 설정
from mem0.configs.base import MemoryConfig
custom_config = MemoryConfig(
    # 사용자 정의 설정을 이곳에 작성
)
memory = AsyncMemory(config=custom_config)
```

> 확인: 초기화 직후 `await memory.search(...)`를 한 번 실행한다. 오류 없이 memory를 반환하면 설정이 동작하는 것이다.

> 팁: vector store connection을 매번 새로 만들지 않고 여러 worker에서 재사용할 수 있도록 config object를 async client 가까이에 둔다.

### Lifecycle과 동시성 관리

```python
import asyncio
from contextlib import asynccontextmanager
from mem0 import AsyncMemory

@asynccontextmanager
async def get_memory():
    memory = AsyncMemory()
    try:
        yield memory
    finally:
        # 필요하다면 resource를 정리
        pass

async def safe_memory_usage():
    async with get_memory() as memory:
        return await memory.search("test query", filters={"user_id": "alice"})
```

> 팁: clean shutdown이 필요할 때(예: FastAPI startup/shutdown hook 내부) client를 async context manager로 감싼다.

```python
async def batch_operations():
    memory = AsyncMemory()

    tasks = [
        memory.add(
            messages=[{"role": "user", "content": f"Message {i}"}],
            user_id=f"user_{i}"
        )
        for i in range(5)
    ]

    results = await asyncio.gather(*tasks, return_exceptions=True)
    for i, result in enumerate(results):
        if isinstance(result, Exception):
            print(f"Task {i} failed: {result}")
        else:
            print(f"Task {i} completed successfully")
```

> 확인: concurrency가 올바르게 동작하면 성공 task는 memory ID를 반환하고 실패는 `results` 목록의 exception으로 나타난다.

### Retry로 복원력 추가

```python
import asyncio
from mem0 import AsyncMemory

async def with_timeout_and_retry(operation, max_retries=3, timeout=10.0):
    for attempt in range(max_retries):
        try:
            return await asyncio.wait_for(operation(), timeout=timeout)
        except asyncio.TimeoutError:
            print(f"Timeout on attempt {attempt + 1}")
        except Exception as exc:
            print(f"Error on attempt {attempt + 1}: {exc}")

        if attempt < max_retries - 1:
            await asyncio.sleep(2 ** attempt)

    raise Exception(f"Operation failed after {max_retries} attempts")

async def robust_memory_search():
    memory = AsyncMemory()

    async def search_operation():
        return await memory.search("test query", filters={"user_id": "alice"})

    return await with_timeout_and_retry(search_operation)
```

> 경고: retry 횟수에는 항상 상한을 둔다. 무한 loop는 event loop를 계속 점유해 다른 task를 막을 수 있다.

## 동작 예시

### 핵심 작업

```python
# Memory 생성
result = await memory.add(
    messages=[
        {"role": "user", "content": "I'm travelling to SF"},
        {"role": "assistant", "content": "That's great to hear!"}
    ],
    user_id="alice"
)

# Memory 검색
results = await memory.search(
    query="Where am I travelling?",
    filters={"user_id": "alice"}
)

# Memory 목록
all_memories = await memory.get_all(filters={"user_id": "alice"})

# 특정 memory 가져오기
specific_memory = await memory.get(memory_id="memory-id-here")

# Memory 수정
updated_memory = await memory.update(
    memory_id="memory-id-here",
    text="I'm travelling to Seattle"
)

# Memory 삭제
await memory.delete(memory_id="memory-id-here")

# Scope에 속한 memory 삭제
await memory.delete_all(user_id="alice")
```

> 확인: 각 호출은 synchronous client와 같은 response field(ID, `results`, confirmation object)를 반환해야 한다. key가 없으면 대개 coroutine을 await하지 않은 것이다.

> 참고: `delete_all`은 `user_id`, `agent_id`, `run_id` 중 하나 이상을 요구한다. 단일 session으로 삭제 범위를 좁히려면 세 값을 모두 제공한다.

### Scope 기반 정리

```python
await memory.add(
    messages=[{"role": "user", "content": "I prefer vegetarian food"}],
    user_id="alice",
    agent_id="diet-assistant",
    run_id="consultation-001"
)

all_user_memories = await memory.get_all(filters={"user_id": "alice"})
agent_memories = await memory.get_all(filters={"user_id": "alice", "agent_id": "diet-assistant"})
session_memories = await memory.get_all(filters={"user_id": "alice", "run_id": "consultation-001"})
specific_memories = await memory.get_all(
    filters={"user_id": "alice", "agent_id": "diet-assistant", "run_id": "consultation-001"}
)

history = await memory.history(memory_id="memory-id-here")
```

> 팁: compliance 또는 update logic debugging을 위해 audit trail이 필요할 때 `history`를 사용한다.

### 다른 async API와 결합

```python
import asyncio
from openai import AsyncOpenAI
from mem0 import AsyncMemory

async_openai_client = AsyncOpenAI()
async_memory = AsyncMemory()

async def chat_with_memories(message: str, user_id: str = "default_user") -> str:
    search_result = await async_memory.search(query=message, filters={"user_id": user_id}, top_k=3)
    relevant_memories = search_result["results"]
    memories_str = "\n".join(f"- {entry['memory']}" for entry in relevant_memories)

    system_prompt = (
        "You are a helpful AI. Answer the question based on query and memories.\n"
        f"User Memories:\n{memories_str}"
    )

    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": message},
    ]

    response = await async_openai_client.chat.completions.create(
        model="gpt-5-mini",
        messages=messages
    )

    assistant_response = response.choices[0].message.content
    messages.append({"role": "assistant", "content": assistant_response})
    await async_memory.add(messages, user_id=user_id)

    return assistant_response
```

> 확인: 모든 연결이 올바르면 OpenAI 응답은 최근 memory를 반영하고, 후속 `add` 호출은 새 assistant turn을 영속화해야 한다.

### 오류를 우아하게 처리하기

```python
from mem0 import AsyncMemory
from mem0.configs.base import MemoryConfig

async def handle_initialization_errors():
    try:
        config = MemoryConfig(
            vector_store={"provider": "chroma", "config": {"path": "./chroma_db"}},
            llm={"provider": "openai", "config": {"model": "gpt-5-mini"}}
        )
        AsyncMemory(config=config)
        print("AsyncMemory initialized successfully")
    except ValueError as err:
        print(f"Configuration error: {err}")
    except ConnectionError as err:
        print(f"Connection error: {err}")

async def handle_memory_operation_errors():
    memory = AsyncMemory()
    try:
        await memory.get(memory_id="non-existent-id")
    except ValueError as err:
        print(f"Invalid memory ID: {err}")

    try:
        await memory.search(query="", filters={"user_id": "alice"})
    except ValueError as err:
        print(f"Invalid search query: {err}")
```

> 경고: 잘못된 input에서 발생한 `ValueError` exception을 잡아 기록한다. 그렇지 않으면 async stack trace가 background task 내부에서 사라질 수 있다.

### FastAPI로 제공하기

```python
from fastapi import FastAPI, HTTPException
from mem0 import AsyncMemory

app = FastAPI()
memory = AsyncMemory()

@app.post("/memories/")
async def add_memory(messages: list, user_id: str):
    try:
        result = await memory.add(messages=messages, user_id=user_id)
        return {"status": "success", "data": result}
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))

@app.get("/memories/search")
async def search_memories(query: str, user_id: str, limit: int = 10):
    try:
        result = await memory.search(query=query, filters={"user_id": user_id}, top_k=limit)
        return {"status": "success", "data": result}
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
```

> 팁: FastAPI를 사용할 때는 process당 `AsyncMemory` instance 하나를 만든다. startup hook은 설정하고 재사용하기에 좋은 위치다.

### Logging 계측

```python
import logging
import time
from functools import wraps

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def log_async_operation(operation_name):
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            start_time = time.time()
            logger.info(f"Starting {operation_name}")
            try:
                result = await func(*args, **kwargs)
                duration = time.time() - start_time
                logger.info(f"{operation_name} completed in {duration:.2f}s")
                return result
            except Exception as exc:
                duration = time.time() - start_time
                logger.error(f"{operation_name} failed after {duration:.2f}s: {exc}")
                raise
        return wrapper
    return decorator

@log_async_operation("Memory Add")
async def logged_memory_add(memory, messages, user_id):
    return await memory.add(messages=messages, user_id=user_id)
```

> 확인: 기록된 duration은 AsyncMemory를 production에 올린 뒤 regression을 찾아내는 데 필요한 baseline을 제공한다.

## 기능이 동작하는지 검증하기

- 빠른 add/search cycle을 실행하고 반환된 memory content가 입력과 일치하는지 확인한다.
- application log를 검사해 async task가 event loop를 block하지 않고 완료되는지 확인한다.
- FastAPI 또는 다른 framework에서는 health endpoint를 호출해 shared client가 concurrent request를 처리하는지 검증한다.
- retry counter를 모니터링한다. 예기치 않은 급증은 configuration 또는 connectivity 문제를 의미한다.

## 모범 사례

1. **작업을 반드시 await한다.** `await`를 빼먹으면 write를 놓치기 쉽다. linter를 사용하거나 helper wrapper를 추가한다.
2. **삭제 scope를 주의한다.** 과도한 data 삭제를 피하려면 항상 `user_id`, `agent_id`, `run_id`를 제공한다.
3. **일괄 write를 신중하게 한다.** throughput에는 `asyncio.gather`를 쓰되 backend capacity에 맞춰 concurrency 상한을 둔다.
4. **문맥을 포함해 오류를 기록한다.** user/agent scope를 잡아야 failure를 빠르게 triage할 수 있다.
5. **Client를 재사용한다.** backend handshake를 반복하지 않도록 worker당 한 번 `AsyncMemory`를 instantiate한다.

## 문제 해결

| 문제 | 가능한 원인 | 해결 |
| --- | --- | --- |
| 초기화 실패 | dependency 누락, 잘못된 config | `MemoryConfig` 설정과 environment variable을 검증한다. |
| 느린 작업 | 큰 dataset, network latency | 무거운 query는 cache하고 vector store parameter를 조정한다. |
| Memory를 찾지 못함 | 잘못된 ID 또는 삭제된 record | ID source를 확인하고 soft-deleted state를 처리한다. |
| Connection timeout | network 문제, backend 과부하 | retry/backoff를 적용하고 infrastructure health를 검사한다. |
| Out-of-memory error | 지나치게 큰 batch | concurrency를 줄이거나 작업을 더 작은 chunk로 나눈다. |
