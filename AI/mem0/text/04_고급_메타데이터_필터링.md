# 고급 메타데이터 필터링

> 원문: [Enhanced Metadata Filtering](https://docs.mem0.ai/open-source/features/metadata-filtering)  
> 원문 제공일: 2026-07-18  
> 문서 인덱스: 전체 문서 인덱스는 <https://docs.mem0.ai/llms.txt>에서 가져올 수 있으며, 이 파일로 사용 가능한 모든 페이지를 찾을 수 있다.

> 정확한 OSS memory 검색을 위한 세밀한 메타데이터 질의

Mem0의 고급 메타데이터 필터링은 memory metadata를 대상으로 복잡한 질의를 실행할 수 있게 한다. 비교 연산, 논리 연산자, 와일드카드 일치를 조합해 에이전트에 필요한 정확한 memory를 좁혀 갈 수 있다.

---

## 기능 구성

### 연산자 빠른 참조

| 연산자 | 의미 | 사용 시점 |
| --- | --- | --- |
| `eq` / `ne` | 같음 / 같지 않음 | 문자열, 숫자, 불리언의 정확한 일치 |
| `gt` / `gte` | 초과 / 이상 | 점수, 신뢰도 또는 숫자 필드 기준으로 결과의 범위를 정할 때 |
| `lt` / `lte` | 미만 / 이하 | 평점, timestamp 등의 숫자 값 상한을 둘 때 |
| `in` / `nin` | 목록에 포함 / 목록에 포함되지 않음 | 여러 filter를 연결하지 않고 값의 집합을 허용하거나 차단할 때 |
| `contains` / `icontains` | 대소문자 구분 / 구분하지 않는 부분 문자열 일치 | 텍스트 필드에서 키워드를 검색할 때 |
| `*` | 와일드카드 | 값과 무관하게 필드의 존재를 요구할 때 |
| `AND` / `OR` / `NOT` | filter 조합 | 여러 조건이 함께 동작하도록 논리 트리를 만들 때 |

### 메타데이터 선택자

metadata 필드의 직접 일치가 필요하면 key-value filter부터 시작한다.

```python
from mem0 import Memory

m = Memory()

# 단순 메타데이터 필터로 검색
results = m.search(
    "내 선호는 무엇인가요?",
    filters={"user_id": "alice", "category": "preferences"}
)
```

> 확인: 지정한 `user_id`에서 `category="preferences"`로 tag된 memory만 반환되어야 한다.

### 비교 연산자

score, confidence 또는 숫자 필드를 기준으로 결과 범위를 정하려면 greater-than/less-than 비교를 조합한다. equality helper(`eq`, `ne`)는 문자열과 불리언 검사를 명시적으로 유지한다.

```python
# 초과 / 미만
results = m.search(
    "최근 활동",
    filters={
        "user_id": "alice",
        "score": {"gt": 0.8},
        "priority": {"gte": 5},
        "confidence": {"lt": 0.9},
        "rating": {"lte": 3}
    }
)

# 동등성 연산자
results = m.search(
    "특정 콘텐츠",
    filters={
        "user_id": "alice",
        "status": {"eq": "active"},
        "archived": {"ne": True}
    }
)
```

### 목록 기반 연산자

여러 equality 검사를 작성하지 않고 특정 값을 사전 허용하거나 제외하려면 `in`, `nin`을 사용한다.

```python
# 포함 / 미포함 연산자
results = m.search(
    "여러 카테고리 검색",
    filters={
        "user_id": "alice",
        "category": {"in": ["food", "travel", "entertainment"]},
        "status": {"nin": ["deleted", "archived"]}
    }
)
```

> 확인: 응답에는 허용 목록의 카테고리에 속하는 memory만 포함되고, archived 또는 deleted 상태의 memory는 빠져야 한다.

### 문자열 연산자

`contains`와 `icontains`는 부분 문자열 일치를 수행한다. 관련 없는 memory를 검색하지 않고도 description이나 tag 필드에서 키워드를 찾기 쉽다.

```python
# 텍스트 일치 연산자
results = m.search(
    "콘텐츠 검색",
    filters={
        "user_id": "alice",
        "title": {"contains": "meeting"},
        "description": {"icontains": "important"},
        "tags": {"contains": "urgent"}
    }
)
```

### 와일드카드 일치

값이 무엇이든 해당 필드가 존재하기만 하면 일치하도록 할 수 있다. 필드의 존재 자체가 중요한 경우에 유용하다.

```python
# 필드의 모든 값과 일치
results = m.search(
    "category가 있는 모든 memory",
    filters={
        "user_id": "alice",
        "category": "*"
    }
)
```

### 논리 조합

`AND`, `OR`, `NOT`으로 복잡한 의사결정 트리를 표현한다. 논리 연산자를 중첩해 여러 분기의 workflow를 인코딩할 수 있다.

```python
# 논리 AND
results = m.search(
    "복잡한 질의",
    filters={
        "user_id": "alice",
        "AND": [
            {"category": "work"},
            {"priority": {"gte": 7}},
            {"status": {"ne": "completed"}}
        ]
    }
)

# 논리 OR
results = m.search(
    "유연한 질의",
    filters={
        "user_id": "alice",
        "OR": [
            {"category": "urgent"},
            {"priority": {"gte": 9}},
            {"deadline": {"contains": "today"}}
        ]
    }
)

# 논리 NOT
results = m.search(
    "제외 질의",
    filters={
        "user_id": "alice",
        "NOT": [
            {"category": "archived"},
            {"status": "deleted"}
        ]
    }
)

# 복잡한 중첩 논리
results = m.search(
    "고급 질의",
    filters={
        "user_id": "alice",
        "AND": [
            {
                "OR": [
                    {"category": "work"},
                    {"category": "personal"}
                ]
            },
            {"priority": {"gte": 5}},
            {
                "NOT": [
                    {"status": "archived"}
                ]
            }
        ]
    }
)
```

> 확인: 응답 metadata를 검사한다. 반환된 각 memory는 조합된 논리 트리를 정확히 만족해야 한다. 결과 범위가 지나치게 넓다면 vector store로 보낸 raw filter를 기록한다.

## 설정

filter가 많은 질의도 빠르게 유지하려면 vector store를 조정한다. 자주 filtering하는 필드는 index를 만들고, 복잡한 검사는 evaluation 순서의 뒤쪽에 둔다.

```python
# vector store가 filtering 대상 필드의 indexing을 지원하는지 확인
config = {
    "vector_store": {
        "provider": "qdrant",
        "config": {
            "host": "localhost",
            "port": 6333,
            "indexed_fields": ["category", "priority", "status", "user_id"]
        }
    }
}
```

> 확인: indexing을 활성화한 뒤 같은 질의를 benchmark한다. store가 vector scoring 전에 indexed field로 document를 제거할 수 있으면 latency가 줄어야 한다.

> 팁: 단순한 `key=value` filter를 indexed field에 먼저 두고, 그 뒤에 range 또는 텍스트 조건을 둔다. 그러면 store가 결과를 초기에 줄일 수 있다.

```python
# 더 효율적: indexed field의 filter를 먼저 적용
good_filters = {
    "user_id": "alice",
    "AND": [
        {"category": "work"},
        {"content": {"contains": "meeting"}}
    ]
}

# 덜 효율적: 복잡한 연산을 먼저 적용
avoid_filters = {
    "user_id": "alice",
    "AND": [
        {"description": {"icontains": "complex text search"}}
    ]
}
```

> 확인: indexed field를 앞에 둔 `good_filters` 예시처럼 filter 순서를 바꾸면, 단순 check보다 비싼 텍스트 검색을 먼저 하는 `avoid_filters` 패턴보다 질의가 일반적으로 더 빨리 반환된다.

vector store 지원 범위는 서로 다르므로 배포 전에 연산자 지원 여부를 확인한다.

| Vector store | 지원 범위 |
| --- | --- |
| Qdrant | 비교, 목록, 논리 연산을 모두 지원한다. 깊게 중첩된 boolean logic도 효율적으로 처리한다. |
| Chroma | equality와 기본 비교만 지원한다. 중첩이 제한적이므로 큰 트리는 더 작은 호출로 나눈다. |
| Pinecone | 비교 및 `in`/`nin`을 지원한다. 텍스트 연산은 제약이 있으므로 가능한 tag에 의존한다. |
| Weaviate | 고급 텍스트 filter를 포함한 모든 연산자를 지원한다. hybrid text + metadata 질의가 필요할 때 가장 좋은 선택이다. |

> 경고: 연산자가 지원되지 않으면 대부분의 store는 해당 branch를 조용히 무시한다. 실행 전에 validation을 추가해 빈 결과를 반환하는 대신 더 단순한 질의로 fallback할 수 있게 한다.

### 이전 filter에서 마이그레이션

```python
# 이전(v0.x): 단순 key-value filtering만 사용
results = m.search(
    "query",
    filters={"user_id": "alice", "category": "work", "status": "active"}
)

# 이후(v1.0.0): 연산자를 사용하는 고급 filtering
results = m.search(
    "query",
    filters={
        "user_id": "alice",
        "AND": [
            {"category": "work"},
            {"status": {"ne": "archived"}},
            {"priority": {"gte": 5}}
        ]
    }
)
```

> 참고: 기존 equality filter는 계속 동작한다. 새 연산자 branch를 점진적으로 추가하면 agent가 downtime 없이 더 풍부한 질의를 채택할 수 있다.

## 동작 예시

### 프로젝트 관리 filtering

```python
# 높은 우선순위의 활성 task 찾기
results = m.search(
    "어떤 task에 주의가 필요한가요?",
    filters={
        "user_id": "project_manager",
        "AND": [
            {"project": {"in": ["alpha", ""]}},
            {"priority": {"gte": 8}},
            {"status": {"ne": "completed"}},
            {
                "OR": [
                    {"assignee": "alice"},
                    {"assignee": "bob"}
                ]
            }
        ]
    }
)
```

> 확인: 반환된 task는 대상 프로젝트에 속하고, 완료되지 않았으며, 지정한 팀원 중 한 명에게 할당되어야 한다.

### 고객 지원 filtering

```python
# 최근에 해결되지 않은 ticket 찾기
results = m.search(
    "처리 중인 지원 이슈",
    filters={
        "agent_id": "support_bot",
        "AND": [
            {"ticket_status": {"ne": "resolved"}},
            {"priority": {"in": ["high", "critical"]}},
            {"created_date": {"gte": "2024-01-01"}},
            {
                "NOT": [
                    {"category": "spam"}
                ]
            }
        ]
    }
)
```

> 팁: shared support bot이 현재 session에서 처리할 수 있는 ticket만 반환하도록 agent ID filter와 ticket별 metadata를 함께 사용한다.

### 콘텐츠 추천 filtering

```python
# 개인화된 콘텐츠 filtering
results = m.search(
    "콘텐츠 추천",
    filters={
        "user_id": "reader123",
        "AND": [
            {
                "OR": [
                    {"genre": {"in": ["sci-fi", "fantasy"]}},
                    {"author": {"contains": "favorite"}}
                ]
            },
            {"rating": {"gte": 4.0}},
            {"read_status": {"ne": "completed"}},
            {"language": "english"}
        ]
    }
)
```

> 확인: 개인화된 feed에는 평점과 언어 조건을 만족하는 미완독 title만 표시되어야 한다.

### 잘못된 연산자 처리

```python
try:
    results = m.search(
        "test query",
        filters={
            "user_id": "alice",
            "invalid_operator": {"unknown": "value"}
        }
    )
except ValueError as e:
    print(f"Filter error: {e}")
    results = m.search(
        "test query",
        filters={"user_id": "alice", "category": "general"}
    )
```

> 경고: 개발 중에 오타나 지원되지 않는 연산자를 잡을 수 있도록 검색 실행 전에 filter를 validation한다. runtime에서 잡는 것보다 안전하다.

## 기능이 동작하는지 검증하기

- vector store로 전송한 filter를 기록하고 응답 metadata가 모든 절을 만족하는지 확인한다.
- indexing 전후의 질의를 benchmark하여 latency 개선이 실제로 나타나는지 확인한다.
- 연산자 validation에 실패했을 때 fallback이 얼마나 자주 실행되는지 analytics 또는 debug logging으로 추적한다.

---

## 모범 사례

1. **indexed field를 먼저 사용한다.** equality check가 복잡한 문자열 연산보다 먼저 실행되도록 filter 순서를 둔다.
2. **연산자를 의도적으로 조합한다.** 큰 중첩 구조는 debug하기 어려우므로 논리 트리를 읽기 쉽게 유지한다.
3. **성능을 정기적으로 시험한다.** production과 유사한 payload로 핵심 질의를 benchmark한다.
4. **우아한 성능 저하를 계획한다.** 연산자를 사용할 수 없을 때의 fallback filter를 제공한다.
5. **문법을 일찍 검증한다.** 잘못된 filter를 일찍 잡아 agent를 보호한다.
