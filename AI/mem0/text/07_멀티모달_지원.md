# 멀티모달 지원

> 원문: 사용자가 제공한 Mem0 문서 `Multimodal Support`  
> 원문 제공일: 2026-07-18  
> 문서 인덱스: 전체 문서 인덱스는 <https://docs.mem0.ai/llms.txt>에서 가져올 수 있으며, 이 파일로 사용 가능한 모든 페이지를 찾을 수 있다.

> 텍스트와 이미지 모두에서 memory를 포착하고 recall한다.

멀티모달 지원은 Mem0가 일반 텍스트와 함께 이미지에서도 fact를 추출하게 한다. screenshot, receipt, product photo를 추가하면 Mem0가 그 insight를 검색 가능한 memory로 저장하므로 agent가 나중에 recall할 수 있다.

> **다음 상황에서 사용한다.**
>
> - 사용자가 screenshot, menu, document를 공유하고 그 detail을 memory로 만들고 싶다.
> - 이미 텍스트 대화를 수집하지만 더 나은 답을 위해 visual context가 필요하다.
> - URL과 로컬 image file을 모두 다루는 단일 workflow가 필요하다.

> 경고: Mem0는 image를 설정된 vision model에 그대로 전달하므로, image별 크기와 해상도 제한은 해당 provider에서 온다(예: OpenAI는 image를 20 MB로 제한한다). 큰 file은 provider limit 안에 머물고 처리 속도를 유지하도록 compress 또는 resize한다.

---

## 기능 구성

- **Vision 처리:** Mem0가 image를 vision model로 실행해 텍스트와 핵심 detail을 추출한다.
- **Memory 생성:** 추출한 정보는 standard memory로 저장되므로 search, filter, analytics가 계속 동작한다.
- **Context 연결:** 같은 대화의 visual turn과 textual turn이 연결된 상태로 유지되어 agent에 더 풍부한 context를 제공한다.
- **유연한 입력:** Python/JavaScript SDK 모두 publicly accessible URL 또는 base64-encoded local file을 받는다.

### 지원 format

| Format | 용도 | 참고 |
| --- | --- | --- |
| JPEG / JPG | 사진과 screenshot | camera capture의 기본 선택지 |
| PNG | 투명도가 있는 image | 선명한 text와 UI element를 유지 |
| WebP | web에 최적화된 image | 더 빠른 upload를 위한 작은 payload |
| GIF | 정적 또는 animated graphic | 단순 graphic과 짧은 loop에 동작 |

---

## 설정

> 경고: image content를 처리하려면 LLM config에 반드시 `enable_vision: True`를 설정해야 한다. 설정하지 않으면 image turn은 조용히 drop되고 vision memory도 생성되지 않는다.

```python
config = {"llm": {"provider": "openai", "config": {"enable_vision": True, "vision_details": "auto"}}}
client = Memory.from_config(config)
```

> 참고: `vision_details`는 vision model의 image `detail` 설정에 대응하며 기본값인 `"auto"`, `"low"`, `"high"`를 받는다. receipt나 document처럼 조밀한 image에는 `"high"`를 사용한다. 단순 photo에서는 `"low"`가 더 빠르고 저렴하다.

### URL의 image message 추가

```python
from mem0 import Memory

client = Memory()

messages = [
    {"role": "user", "content": "Hi, my name is Alice."},
    {
        "role": "user",
        "content": {
            "type": "image_url",
            "image_url": {
                "url": "https://example.com/menu.jpg"
            }
        }
    }
]

client.add(messages, user_id="alice")
```

```typescript
import { Memory } from "mem0ai/oss";

const client = new Memory();

const messages = [
  { role: "user", content: "Hi, my name is Alice." },
  {
    role: "user",
    content: {
      type: "image_url",
      image_url: { url: "https://example.com/menu.jpg" }
    }
  }
];

await client.add(messages, { userId: "alice" });
```

> 확인: response payload를 검사한다. memory 목록에는 menu image에서 추출한 항목과 text turn에서 추출한 항목이 모두 포함되어야 한다.

### 로컬 image를 base64로 upload

```python
import base64
from mem0 import Memory

def encode_image(image_path):
    with open(image_path, "rb") as image_file:
        return base64.b64encode(image_file.read()).decode("utf-8")

client = Memory()
base64_image = encode_image("path/to/your/image.jpg")

messages = [
    {
        "role": "user",
        "content": [
            {"type": "text", "text": "What's in this image?"},
            {
                "type": "image_url",
                "image_url": {
                    "url": f"data:image/jpeg;base64,{base64_image}"
                }
            }
        ]
    }
]

client.add(messages, user_id="alice")
```

```typescript
import fs from "fs";
import { Memory } from "mem0ai/oss";

function encodeImage(imagePath: string) {
  const buffer = fs.readFileSync(imagePath);
  return buffer.toString("base64");
}

const client = new Memory();
const base64Image = encodeImage("path/to/your/image.jpg");

const messages = [
  {
    role: "user",
    content: [
      { type: "text", text: "What's in this image?" },
      {
        type: "image_url",
        image_url: {
          url: `data:image/jpeg;base64,${base64Image}`
        }
      }
    ]
  }
];

await client.add(messages, { userId: "alice" });
```

> 팁: 작은 image일수록 upload와 처리가 빠르다. base64 encoding 전에 compress 또는 resize하고, 큰 file에는 vision provider의 image별 크기 제한을 확인한다.

## 동작 예시

### Restaurant menu memory

```python
from mem0 import Memory

client = Memory()

messages = [
    {
        "role": "user",
        "content": "어떤 요리를 좋아했는지 기억하도록 도와줘."
    },
    {
        "role": "user",
        "content": {
            "type": "image_url",
            "image_url": {
                "url": "https://example.com/restaurant-menu.jpg"
            }
        }
    },
    {
        "role": "user",
        "content": "나는 땅콩 알레르기가 있고 채식 식사를 선호해."
    }
]

result = client.add(messages, user_id="user123")
print(result)
```

> 확인: 응답은 allergy note와 photo에서 추출한 menu item을 모두 포착해야 하므로, 이후 검색에서 두 정보를 결합할 수 있다.

### Document 포착

messages = [

### 오류 처리

```python
from mem0 import Memory

client = Memory()

try:
    messages = [{
        "role": "user",
        "content": {
            "type": "image_url",
            "image_url": {"url": "https://example.com/image.jpg"}
        }
    }]

    client.add(messages, user_id="user123")
    print("Image processed successfully")

except ValueError as exc:
    # image_url part에 url이 없을 때 발생
    print(f"Invalid image message: {exc}")
except Exception as exc:
    # image download 또는 vision model 호출이 실패했을 때 발생
    print(f"Could not process image: {exc}")
```

```typescript
import { Memory } from "mem0ai/oss";

const client = new Memory();

try {
  const messages = [{
    role: "user",
    content: {
      type: "image_url",
      image_url: { url: "https://example.com/image.jpg" }
    }
  }];

  await client.add(messages, { userId: "user123" });
  console.log("Image processed successfully");
} catch (error: any) {
  // image_url 누락, download 실패, vision model 오류가 여기로 전달됨
  console.log(`Could not process image: ${error.message}`);
}
```

> 경고: 잘못된 format은 빠르게 실패시켜 context를 잃기 전에 사용자에게 재업로드를 요청할 수 있게 한다.

## 기능이 동작하는지 검증하기

- `add` 호출 뒤 반환된 memory를 검사해 image-derived text(menu item, receipt total 등)가 포함됐는지 확인한다.
- image detail을 대상으로 후속 `search`를 실행한다. 관련 text와 함께 memory가 나타나야 한다.
- image upload latency를 모니터링한다. 큰 file도 허용 가능한 response time 안에 완료되어야 한다.
- 반복되는 failure를 해결할 수 있도록 file size와 URL source를 기록한다.

---

## 모범 사례

1. **의도를 묻는다.** memory에 올바른 context가 담기도록 사용자가 왜 image를 보냈는지 설명하게 한다.
2. **image를 읽기 쉽게 유지한다.** 더 나은 추출을 위해 무거운 filter나 shadow가 없는 선명한 photo를 권장한다.
3. **대량 upload를 나눈다.** 여러 image는 별도 `add` 호출로 보내 failure를 분리하고 신뢰성을 높인다.
4. **Privacy를 주시한다.** 환경이 해당 data를 안전하게 처리하도록 구성되지 않았다면 민감한 document를 upload하지 않는다.
5. **File size를 일찍 검증한다.** encoding 전에 file size를 검사해 bandwidth와 시간을 절약한다.

---

## 문제 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| Upload 거부 | image가 vision provider의 size limit 초과 | 전송 전 compress 또는 resize |
| Memory에 image data 누락 | 저품질 또는 흐린 image | 조명이 더 좋은 환경에서 다시 촬영 |
| 잘못된 format 오류 | 지원하지 않는 file type | 먼저 JPEG 또는 PNG로 변환 |
| 느린 처리 | 고해상도 image | 5 MB 미만으로 downscale 또는 compress |
| Base64 오류 | 잘못된 prefix 또는 encoding | `data:image/<type>;base64,`가 있고 문자열이 유효한지 확인 |
